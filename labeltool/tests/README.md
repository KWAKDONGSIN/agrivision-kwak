## 3. 모래상자 — 공용 자료를 건드리지 않는다

`tests/run_all.sh` 는 **자기 모래상자를 스스로 만듭니다.**

```
tests/_sandbox/
  sb_main/          app + export + data 실복사 (t1_api · browser)
  sb_reg/           같은 것 (regress_all)
  sb_base/          같은 것 + 얼려 둔 판정 자료 (기준선)
  dataset_sample/   고정 표본 12장만 담은 작은 «원본 폴더»
  merged/           통합 시험의 격리 사본
```

- 서버는 **빈 포트**를 스스로 찾습니다(5401~ · 5501~ · 5601~). 실서버 **5111** 과 교수님 **5100·5101·5105**
  는 목록에서 아예 빼 놓았고(`sandbox.KEEP_OUT`), 이미 쓰이는 포트면 **멈춥니다.**
- 끝나면 **내가 띄운 PID 만** 끕니다. `pkill` 을 쓰지 않습니다.
- 쓰기는 `tests/_sandbox/` 안에서만. 공용 `data/`·`exports/`·데이터셋·팀원 폴더는 **읽기만** 합니다.
- 스크린샷은 `~/ff_shots/tests_260920/` 에만.
- `tests/_sandbox/` 와 `tests/_out/` 은 **지워도 됩니다**(다시 만들어집니다).

## 4. 기준선(baseline) — «동작이 안 바뀌었다» 는 증거

리팩터는 **동작을 바꾸지 않는 것**이 조건입니다. 그것을 사람 눈이 아니라 숫자로 확인하려고
리팩터 **전** 코드의 동작을 `tests/fixtures/baseline_260920/` 에 굳혀 두었습니다.

| 담긴 것 | 뭐냐 | 다르면 |
|---|---|---|
| ① `api/*.json` (**100개**) | 고정 표본 12장에 대한 API 응답 — 시각·PID·경로처럼 **변하는 칸은 `⟨지움⟩`** 으로 바꾼 뒤. `api_*` 50개 = 손대기 **전**(확정 0건) · `api2_*` 50개 = 상자 저장 + 사람 확정을 한 **뒤** | **실패** |
| ② `exports.json` (**99개**) | 모래상자 내보내기(네 과일 × 마스크·번호·상자·개수 · «AI 제안 포함» + 사과는 «사람 확정만» 도) 산출 파일 sha256 | **실패** |
| ② `exports.json` 의 `peach__after_writes` | ⑤ 의 쓰기가 끝난 뒤 한 번 더 내보낸 것(②  99 → **119**) | **실패** |
| ③ `bundles.json` (15개) | 묶음별 통과/실패 수. **이번 실행에서 안 돌린 묶음은 경고**(`--only=` 로 돌리면 나머지가 비어 있는 것이 정상) | 실패 수가 늘거나 통과 수가 **줄면** 실패 |
| ④ `code_sha256.json` (30개) | 정적 파일·서버 코드 sha256 | 경고만(리팩터하면 당연히 바뀐다) |
보안 관련 값·설정 세부는 공개본에서 생략했습니다.

**라우트 덮개: 37개 중 37개.** (2026-09-19 2차 검수 전에는 **11개**였습니다 — ① 은 GET 7개뿐이라
`/api/boxes_export`·`/api/save_instances`·`/api/component`·중복 묶음 다섯 개 같은 **19개 라우트를
어느 시험도 부르지 않았습니다.** 그래서 `boxes.py` 가 실제로 동작을 바꿨는데 기준선이 «0개» 라고 한
일이 있었습니다 — `cycles/260920_structure/cycle_1/stage2_review.md` §1-1.)

```bash
bash tests/run_all.sh --check-baseline     # 대조 → 다른 칸을 표로
bash tests/run_all.sh --rebaseline         # 새로 뜨기 (옛 판은 fixtures/_baseline_prev/ 에 10판 남는다)
bash tests/run_all.sh --clean              # 모래상자·로그를 지운다 (실패가 남긴 모래상자가 GB 로 쌓인다)
```

- 고정 표본: `tests/fixtures/stems.txt` — 과일마다 **이름 오름차순 첫 3장** (복숭아·포도·사과·블루베리 × 3 = 12장)
- 얼려 둔 판정 자료: `tests/fixtures/status_260920/` — 그 12장 몫의 `status.json`·`duplicates.json` 만.
  **이게 중요합니다**: 공용 `data/status.json` 을 그대로 쓰면 사람이 실서버에서 라벨을 고칠 때마다
  기준선이 흔들립니다. 얼려 두었으니 기준선은 **코드만의 함수**입니다.
- 표본 데이터셋도 12장만 만들기 때문에 기준선 한 번이 **약 12초**입니다(네 과일 전부 내보내면 수 분).
- **확정 상태는 서버에게 시켜서 만듭니다.** 공용 `data/status.json` 에는 2026-09-19 현재
  `confirmed_*` 기록이 **한 건도 없습니다**(확정 기능이 새것이라 아직 아무도 안 썼습니다).
  그대로 두면 기준선이 «확정» 관련 길을 하나도 지나지 않습니다. 그래서 `snapshot.py` 가
  ① 을 먼저 뜨고 → 표본 12장에 고정 상자를 저장하고 → `/api/status` 로 과일마다
  «마스크 ok · 상자 fixed · 번호 ok» 를 한 장씩 확정한 뒤 → `api2_*` 를 한 벌 더 뜹니다.
  JSON 을 손으로 지어내지 않으므로 **규칙은 늘 코드가 정합니다.**
