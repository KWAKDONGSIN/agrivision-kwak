## ① 결론 — 합격
- N2(판정 단추가 화면 밖) 해결: 2차가 다섯 창(1100×700 포함) × 세 작업 × 더보기 접힘/펼침 30벌에서 5/5 를 다른 스크립트로 재현. 1280 이상은 한 겹·캔버스 60% 이상.

- 1차가 안 한 조작(«AI 제안으로 교체» 실행 뒤 화소 대조 0, «수정본 되돌리기» 뒤 파일 삭제, 중복 일괄 제외 3→86→3)을 모래상자에서 51/51. 회귀 31/31·50/50. 공용 `data/` 는 (총괄이 갱신한 4파일을 빼고) 전후 동일.

## ③ 사이클 3 이 할 일 (확정 · 우선순위순) — 주제: 녹취 «일일이 우리가 할 수는 없으니까» + 남은 다듬기
보안 관련 값·설정 세부는 공개본에서 생략했습니다.
1. **중복 묶음을 한 번에**: `/api/item` 에 `dup_rep`(그 묶음의 대표 stem, `dupes.representative_map` 재사용) 추가 → 편집 화면에 묶음 구성원 썸네일 줄(대표에 «남김» 표시, 누르면 그 사진으로 이동, 지금 사진 강조) + **«이 묶음: 대표만 남기고 나머지 제외»** 단추(확인창에 몇 장이 제외되는지, 기존 `/api/save action:exclude` 반복 또는 작은 새 API — 되돌리기 단추도). 이미 사람이 판정한(ok·fixed·flag) 구성원은 건드리지 않음.
2. **의심 종류별 빠른 단추**: `/api/list` 에 `flag=<이름>` 인자 → 목록의 «무엇부터 볼까» 에 과일별로 실제 있는 종류만(예: 사과 «속이 찬 동그라미», 공통 «마스크가 거의 빔») 단추로. 장수 표시.
3. **카운팅 개수 화면**: `/api/instance_stats`(과일별 총 열매 번호 수·사진별 개수, 디스크 캐시 — 번호 파일·이진 마스크의 mtime 이 바뀌면 그 장만 다시 셈, «이진본이 번호본을 자른다» 규칙은 `instances.load_inst` 를 그대로 사용) → 진행 현황 탭에 과일별 합계·장당 평균·최대, 목록 카드에 «N개» 딱지(사과·블루베리). 처음 계산이 오래 걸리면 진행 표시.
4. **목록의 «제외» 가 잘 안 보임**(흐림+테두리뿐) → 상태 딱지(제외·문제 있음·수정함·OK) 추가. 지금 사과 314·블루베리 71장이 제외 상태.
5. M2: 1100×700 에서 위쪽 두 줄이 두 겹이 되는 것 → ③번호 설명과 «할 일» 줄을 좁은 창에서 한 줄로 자르고 전체는 풍선말(검수자 이름은 `#meta` 로만). 합격 기준: 1100×700 에서 캔버스 55% 이상·판정 5/5. 그 아래 폭은 «지원 하한 1100px» 로 README 에 명시.
6. M4 옛 단추 이름 4곳(`app.js:744`·`ui.js:248`·`README:138·392`) · M5 단추 설명 `@media` 문턱 1400→1180px · M6 검색 디바운스에 `isComposing` 확인 · M7 `TH` 표에 `TH_ASOF` 날짜와 «문턱이 낡았을 수 있음» 콘솔 경고, 새 과일은 경고 없이 안전한 기본값 · M3 의 문서 3문장(`help.html:89·120`, `README:96`).
7. 사용성: 세로 사진에서 양옆 검은 벌판 줄이기(옆 패널 폭은 그대로, 캔버스 안에서 사진을 세로에 꽉 맞추는 기본 배율 확인 — 이미 꽉 맞춤이면 손대지 말 것) · 범례의 «알록달록 = 열매 번호» 를 누르면 그 레이어가 꺼지고 켜지게.
- 주황 줄 합집합 33~38%: **합격으로 봄**(종류별 25% 기준은 통과, 과일마다 세 장에 한 장은 «볼 만한 이유» 가 있는 수준). 단 사이클 4 에서 사람 체크리스트에 «경고가 너무 잦다고 느끼면 알려 달라» 한 줄.
