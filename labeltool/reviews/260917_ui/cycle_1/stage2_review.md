## 3. 새로 찾은 문제 (심각도 순)

### N1 🔴 안내 창이 떠 있어도 뒤의 사진에 판정이 나간다 — **고쳤습니다**

첫 방문 안내(또는 `?`)의 **5단계에는 «1 원본 그대로 OK / 3 문제 있음 / 4 제외 / Ctrl+S»** 가 적혀 있습니다.
읽으면서 그 키를 눌러 보는 것이 자연스러운데, `app.js` 의 `keydown` 은 안내 창을 모릅니다.

모래상자 실측(`60_tour_step5_over_edit.png` → `61_tour_after_key1.png`):

```
누르기 전 : {"at":"2026-09-16 11:24","by":"AI 3회 검수(Opus5→Opus5→Fable5.1)","status":"ok"}
1 을 누른 뒤: {"at":"2026-09-17 21:33:11","by":"익명",                        "status":"ok"}
```

**`status.json` 의 검수자 이름과 시각이 덮여 썼습니다.** 상태가 마침 `ok` 였어서 상태값은 안 바뀌었지만,
`unreviewed` 사진이었다면 그대로 «원본 그대로 OK» 로 판정됩니다. 게다가 `doAction` 이 `nextItem()` 을 부르므로
**안내 창 뒤에서 사진이 소리 없이 다음 장으로 넘어갑니다**. `Ctrl+S`·`3`·`4` 도 같습니다.
이것은 **이번 사이클이 안내 창을 넣으면서 새로 생긴** 문제입니다(전에는 안내 창 자체가 없었습니다).

### N2 🔴 판정 단추가 화면에 없다 — 1366×768 에서 **5개 중 0개**

1차는 «판정 칸을 패널 위로 올렸다» 고 했지만, 그 위의 **레이어 칸이 385~404px** 라 결국 밀려납니다.
`#side` 는 스스로 스크롤되는 칸이라 (바깥 스크롤바가 아니라) 스크롤바가 눈에 잘 안 띕니다.

| 창 크기 | `#side` 안쪽 높이 / 보이는 높이 | 판정 칸 위치 | **스크롤 없이 다 보이는 판정 단추** |
|---|---|---|---|
| 1920×1080 | 1433 / 828 | 712 → 1131 | 3 / 5 |
| 1500×950 | 1433 / 698 | 712 → 1131 | **1 / 5** |
| **1366×768** (흔한 노트북) | 1516 / 518 | 688 → 1104 | **0 / 5** |
| 1280×800 | 1516 / 550 | 688 → 1104 | **0 / 5** |

`40_side_1366x768.png` 를 보면 오른쪽 패널에 **레이어 칸만** 보입니다. 처음 온 사람은 «다 봤는데 어디를 눌러야 하지» 가 됩니다.
(단축키 `1`~`4` 는 살아 있지만, 그것은 안내를 읽은 사람만 압니다.)

### N3 🟠 ③ 번호 편집 설명이 **사실과 달랐다** — **고쳤습니다**

`app.js` 를 읽어 보면 D·M·X·N 은 전부 **두 단계**입니다 — 마우스로 «고르기» 만 하고, **키를 눌러야** 고쳐집니다(`numKey`).
그런데 이번 사이클이 새로 넣은 설명은 한 단계인 것처럼 적혀 있었습니다.

- 「지금 할 일」 설명 줄: «알을 **눌러 지우기(D)**·합치기(M) …»
- ③ 칸 단추 풍선말 4개: «잘못 붙은 번호 덩어리를 **눌러 지웁니다** (D)» 등 (**풍선말 자체가 이번에 새로 붙은 것**)

모래상자 실측: 알을 클릭하면 `S.instN` 이 **그대로 118개**, `S.numSel=[60]` (고르기만 됨) → `D` 를 눌러야 117개.
처음 온 사람은 «눌렀는데 안 지워진다» 에서 막힙니다.

### N4 🟠 「이 사진에서 할 일」이 거의 모든 사진에서 같은 말을 한다 (1차 §9-2 가 물은 것)

문턱값은 `added_frac > 1%` · `dice < 0.75` · `suspect_flags` 입니다. 실제 데이터로 세어 보면:

| 과일 | «의심» 이 뜨는 사진 | «AI 와 원본이 많이 다릅니다»(Dice<0.75) |
|---|---|---|
| 사과 (표본 500) | **408장 = 82%** | 224장 = 45% |
| 복숭아 (125) | 57장 = 46% | 16장 = 13% |
| 포도 (500) | 58장 = 12% | 13장 = 3% |
| 블루베리 (500) | 9장 = 2% | 43장 = 9% |

**사과는 10장 중 8장에 «자동 점검이 의심» 이 뜹니다.** 늘 켜져 있는 경고는 경고가 아닙니다.
게다가 한 화면 안에서 «AI 와 원본이 **많이 다릅니다** (Dice 0.00 · **AI누락 0.0%**)» 처럼
«많이 다르다» 와 «0.0%» 가 나란히 찍혀 초보에게는 모순으로 읽힙니다(`40_side_1366x768.png`).

### N5 🟠 딱지(중복#·의심·Dice·번호오류) 뜻 범례가 **1400px 미만에서 통째로 숨는다**

1차 §7-5 의 «가정» 이지만, 결과가 나쁩니다. 1366×768 실측 `display:none` (`70_list_1366.png`).
흔한 노트북에서는 목록에 «Dice 0.00», «의심», «중복#16» 만 뜨고 **그 뜻이 화면 어디에도 없습니다.**
초보를 위해 만든 범례가 정작 초보의 화면에서만 사라집니다.

### N6 🟡 검색 칸은 `Enter` 를 쳐야 듣는데, 그 말이 어디에도 없다

실측: `#f-q` 에 «image301» 을 넣기만 하면 카드 **120장 그대로**, `Enter` 를 치면 **4장**.

### N9 🟡 저장 뒤 「이 사진에서 할 일」이 옆의 «상태» 와 서로 다른 말을 한다 — **안 고쳤습니다**

원인: `app.js` 의 `doAction()` 이 `S.items[S.idx].status` 만 고치고 **`S.item.status` 는 그대로 둡니다**(`app.js:746`).
`ui.js` 의 `tick()` 은 `S.item.status` 로 «바뀌었나» 를 보므로 다시 그리지 않습니다.
`Ctrl+S`(수정본 저장)일 때만 사진이 그대로 남아 이 모순이 눈에 보입니다(`1`·`2`·`3`·`4` 는 다음 장으로 넘어가 가려짐).
**`app.js` 를 고쳐야 하므로 저는 손대지 않았습니다.** 고침 안: `doAction` 의 `if (S.items[S.idx])` 블록에
`if (S.item) S.item.status = j.status.status;` 한 줄(그리고 `S.item.by`/`S.item.at`)을 더하면 됩니다.

## 5. 반박 · 정정 (내가 틀렸던 것 포함)

1. **내 첫 「할 일」 시험 21장이 전부 엉뚱한 사진이었습니다.** `ff.py` 의 `open_photo(stem)` 이 목록을 다시 안 읽는 탓(N6 부수효과)에 16개 «실패» 가 났고, 그대로 보고했으면 **1차를 억울하게 깎을 뻔했습니다.** 정확히 여는 방식으로 고쳐 다시 돌리니 **65/65 통과**. 1차의 주장이 맞습니다.
2. **번호 편집 D·M 이 «안 된다» 고 처음 적었습니다.** 원인은 제가 클릭만 하고 키를 안 눌렀기 때문입니다(`ops.py` 의 실패 2건). `app.js` 를 읽고 두 단계인 것을 알아 다시 시험하니 **D·M·X·N 네 가지 모두 됩니다**(`ops2.py` 12/12). 다만 그 과정에서 **설명 글이 틀렸다는 진짜 문제(N3)** 가 나왔습니다.
3. **`help.html` 의 예시 그림 5장이 깨진 줄 알았습니다** (`naturalWidth=0`). `loading="lazy"` 때문에 아직 안 불러온 것이었고, 아래로 굴리니 `ex1·ex2·ex3·ex5` 가 1500~1800px 로 뜹니다. 파일도 전부 있습니다(`ex4_box.jpg` 121KB 포함). **깨지지 않았습니다 — 1차 잘못 없음.**
4. **「지금 할 일」 3칸이 세로를 많이 먹는다는 지적(발주 메모)에는 반대합니다.** 실측 116px = 창의 14~17% 입니다. 세로를 먹는 것은 **오른쪽 레이어 칸(385~404px)** 입니다.
5. **1차 §7-1 «판정 칸을 세 작업에서 모두 보이게 둔 판단»** — 판단 자체는 옳습니다(키 `1~4` 가 어느 모드에서나 살아 있으므로). 문제는 «보이게 둔다» 고 해 놓고 **실제로는 안 보인다**는 것입니다(N2).
6. **1차 §7-4 «200ms 지연은 사람이 못 느끼는 수준»** — 대체로 맞지만 «항상 일치» 는 아닙니다. 연타 직후 최대 200ms 동안 단추 불과 실제 상태가 다릅니다(§2). 위험은 없습니다(스스로 맞음).
