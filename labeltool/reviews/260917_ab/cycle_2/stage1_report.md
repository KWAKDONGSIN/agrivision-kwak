## 3. 문제 (심각도순)

### P1 【심각】 「일괄 제외 되돌리기」 한 번이면 3차 판정의 제외가 통째로 사라지고, 다시 눌러도 **같은 데이터셋이 나오지 않는다**
- 실측(모래상자, 진짜 클릭): 사과 314장·블루베리 71장이 전부 `unreviewed` 가 되고 «중복: …» 메모도 지워짐.
- 다시 「일괄 제외 적용」 을 누르면 **사과에서 9장이 어긋납니다.**
  새로 제외됨(원래는 데이터셋에 **있는** 사진): `20150919_174151_image196`, `20150921_131346_image601`,
  `20150921_131346_image906`, `20150921_131453_image236`, `20150921_131625_image666`, `_image686`, `_image746`,
  `20150921_131833_image311`, `dataset3_front_870` /
  반대로 되살아남(원래는 **뺀** 사진): `…image201`, `…image596`, `…image911`, `…image231`, `…image671`,
  `…image691`, `…image751`, `…image316`, `dataset3_front_840`.
- 게다가 **flag 가 68 → 59** 로 줄었습니다. 저 9장은 «사람 확인 필요» 딱지와 후보 좌표 메모를 잃고 «제외» 가 됩니다.
- 원인: `dupes.pick_representative` 는 첫 장이 flag/exclude 면 **다음 장으로 대표를 옮깁니다.** 지금은
  나머지가 전부 exclude 라 마지막 줄(«전부 exclude/flag 면 첫 장»)로 떨어져 우연히 맞는 것이고,
  되돌리기로 나머지가 `unreviewed` 가 되는 순간 대표가 옮겨 갑니다.
- 고칠 안(셋 중 하나, 3단계가 고르기):
  1. **duplicates.json 에 대표를 명시**(`"rep"` 칸)하고 `pick_representative` 는 그 값을 그대로 쓴다 —
     화면·내보내기·일괄 제외가 영원히 같은 대표를 본다. (가장 확실)
  2. `pick_representative` 에서 **flag 는 건너뛰지 않는다**(exclude 만 건너뛴다). flag 는 «사람이 볼 것» 이지
     «못 쓰는 사진» 이 아니므로 대표 자격이 있다.
  3. 「일괄 제외 되돌리기」가 **`by` 가 «AI 3회 검수…» 인 항목은 건드리지 않도록** 한다
     (사람이 툴에서 누른 것만 되돌린다).
- 임시 조치: 되돌리기 단추의 확인창에 «이 과일은 2026-09-17 3차 판정이 반영돼 있습니다 — 되돌리면
  그 판정 314장이 지워집니다» 를 넣는 것만으로도 사고는 막힙니다.

### P2 【심각】 번호 편집 저장·되돌리기가 3차 판정의 딱지와 메모를 덮어쓴다
- 실측: 제외된 사진에서 번호를 저장 → `status: exclude → fixed`, 메모 «중복: …» → «번호 편집».
  flag 사진에서 저장 → `flag → fixed`, 메모 «사람 확인 필요: … 774,1418,826,1487 …» → «번호 편집».
  이어서 「번호 되돌리기」를 누르면 → `unreviewed` + «번호 편집 되돌림» (원래 판정은 **복구되지 않음**).
- 즉 **flag 68장은 사람이 손대는 순간 «왜 flag 였는지» 가 사라집니다.** 지금 공용 status.json 에 남은
  «번호 편집 되돌림» 3건이 바로 그 흔적입니다(사이클3 시험이 남긴 것).
- 데이터셋 자체는 흔들리지 않습니다(중복 제외는 duplicates.json 이 하므로 내보내기 687/1124 유지).
- 고칠 안: `api_save_instances`·`api_revert_instances` 가 메모를 **덮어쓰지 말고 앞에 붙이기**
  (`"번호 편집 · (이전) 사람 확인 필요: …"`), 그리고 되돌리기는 `unreviewed` 대신 **직전 status 로 복원**
  (`prev_status` 를 항목에 적어 두면 한 줄로 됩니다).

### P3 【보통】 이미 정리가 끝난 중복 그룹의 대표에게 «4 로 제외하세요» 를 계속 시킨다
- 사과 181장·블루베리 33장(그룹 190·33개 모두 «나머지가 전부 제외» 상태).
- `app/static/ui.js` `renderTodo()` 는 «판정된 사진» 에만 지시문을 감춥니다. 대표는 `unreviewed` 라서
  감춰지지 않습니다.
- 고칠 안: 그룹의 **나머지가 전부 exclude 면** «이 묶음은 이미 정리됐습니다 — 이 사진이 대표입니다»
  로 바꾸기(`m.dup_members` 의 상태를 보면 됩니다. 목록 API 가 이미 상태를 줍니다).

### P4 【보통】 flag 메모의 좌표가 사람에게 쓸모 있는 형태가 아니다
- 사과 66장·블루베리 3장의 메모에 `x1,y1,x2,y2` 가 있고 값은 전부 정상 범위지만, **화면에 그려지지 않습니다.**
  점선 상자는 검출 팀 CSV(`park_seongmoon/apple_check/confirmed_errors.csv`)에서만 나오고,
  flag 메모 좌표와 겹치는 사진은 사과 2장뿐입니다.
- 사진은 1080×1920 → 화면 350px 이라 52×69px 후보를 눈으로 찾기 어렵습니다.
- 고칠 안: 이미 있는 «점선 상자» 그리기를 재사용해 **status 메모에서 `x1,y1,x2,y2` 를 뽑아 그려 주기**
  (정규식 한 줄). 겸사겸사 «이 사진에서 할 일» 줄에 flag 사유 앞부분을 같이 띄우면 좋습니다
  (지금은 아래 한 줄짜리 입력칸에만 있고 잘립니다).

### P5 【낮음】 duplicates.json 에 옛 1차 결과가 섞여 남아 있다

### P6 【낮음】 `rule_pending`(교수님 결정 대기)이 툴에는 전혀 보이지 않는다

  **이미 제외된 사진**에 붙어 있어 물어볼 필요가 없는 것도 섞여 있습니다.
- 고칠 안(선택): 툴에 띄울 필요는 없지만, 교수님께 드릴 목록을 만들 때 «제외된 사진의 rule_pending» 은 빼기.
