### ⚠️ 가장 중요한 발견 — 16비트 PNG 를 캔버스로 읽으면 번호가 전부 0 이 된다

`/instances` 는 **bitdepth 16 · colortype 0** PNG 를 준다(실측). 이것을 기존 코드처럼
`createImageBitmap` → 캔버스 → `getImageData` 로 읽으면 브라우저가 16비트를 8비트로 줄이며
**상위 바이트만** 남긴다. 사과 번호는 1~95 이므로 **전부 0(배경)** 이 되어 기능이 통째로 죽는다.
그래서 `app.js` 안에 **PNG 직접 해독기**(`decodeGrayPng`)를 넣었다 — IHDR 파싱 → IDAT 이어붙이기 →
`DecompressionStream("deflate")` 로 zlib 풀기 → 스캔라인 필터 0~4 되돌리기 → `Uint16Array`.
외부 라이브러리·CDN 없이 표준 API 만 쓴다(실측한 파일에 필터 0·1·2·4 가 모두 들어 있어 전부 구현했다).
저장은 반대 방향으로 **RGBA(번호 = R + G*256)** 로 보낸다(`instances.py` 가 받는 두 형식 중 하나).

### 기능

1. **번호 레이어** (§3-1): 번호마다 다른 색(황금각 색상, 255번을 넘어도 됨) + 무게중심에 **번호 글자**(검은 테두리 흰 글자, 확대해도 크기 유지). `/api/instance_info` 의 `has` 가 참일 때만 레이어 줄·편집 패널이 보이고, 거짓이면 숨는다 → 복숭아·포도는 화면이 전과 똑같다. 진하기 슬라이더 따로(기본 60%), 글자 끄기 따로, 레이어 토글 `J`.
2. **번호 편집 모드** (`K` 또는 체크박스): 켜면 브러시·다각형·스마트 도구·«원본 GT 복사»·«전부 지우기»·**«수정본 저장»**·상자 모드를 모두 잠그고, 끄면 전부 푼다(두 편집이 섞여 저장 규칙이 꼬이는 것을 막는다). 패널에 연한 보라 테두리로 «잠김» 을 보여 준다.
3. **편집 4가지** (§3-2) — 조작 순서는 지시서 표 그대로 «고르고 나서 키»:
   - **지우기 `D`**: 열매 클릭(고르기) → `D` → 그 번호 화소 전부 0
   - **합치기 `M`**: A 클릭 → B 클릭 → `M` → B 를 A 번호로
   - **나누기 `X`**: 열매 위에 선 드래그 → `X` → 선(굵기 1~3px 슬라이더)을 마스크에서 빼고, **조각 수가 실제로 늘었을 때만** 선의 한쪽(중심 기준 외적 부호) 조각들에 «최대+1» 번호. 안 나뉘면 **선까지 되돌려 아무것도 바꾸지 않고** 왜 안 됐는지 안내만 한다
   - **새로 붙이기 `N`**: 다각형(클릭, 오른쪽버튼/Enter 로 마침) 또는 브러시(드래그)로 영역 → `N` → 새 번호. **기존 번호와 겹친 화소는 덮지 않고 뺀다**(몇 화소를 뺐는지 알려 준다)
   - 4-이웃 연결성분을 쓴다. 사과는 «한 알이 잎에 가려 여러 조각» 이 정상이므로(근거 문서 §2) 조각이 여럿인 번호도 조각이 늘었을 때만 나눈다.
4. **되돌리기** (§3-2): `Ctrl+Z` / `Ctrl+Y`. 사진 한 장을 통째로 복사하지 않고 **바뀐 화소만** 기록해 **40단계**까지 쌓는다(요구는 10단계 이상). 되돌리면 편집 횟수 계수도 같이 줄어든다.
5. **저장** (§3-2): `Ctrl+S` 또는 «번호 저장» → `/api/save_instances` 로 RGBA PNG + `counts{erase,merge,split,add}` + 이름. «번호 되돌리기» → `/api/revert_instances`(확인 창). 저장 안 한 번호 편집이 있으면 사진 이동·탭 이동·창 닫기에서 물어본다.
6. **목록 화면** (§3-4): 정렬에 «번호 편집 대상(번호오류 먼저)» 추가, 카드에 `번호오류 N` 딱지. 서버 파일을 못 고치므로 이 정렬은 **화면에서** 한다 — 조건에 맞는 목록을 `page_size=500` 으로 모두 받아(사과 1,001장 = 3번) 오류 건수 내림차순으로 세운 뒤 120장씩 다시 쪽을 나눈다. 편집 화면을 열면 오류 CSV 의 상자를 **빨간 점선**으로 그리고 `verdict`(쉬운 한국어)·`inst_ids` 를 상자 위 글자와 옆 패널에 함께 보여 준다.

### ⚠️ `X` 키 충돌 결정 (지시서가 보고를 요구한 항목)

`X` 는 원래 «상자 모드 토글» 이다. **번호 편집 모드가 켜져 있을 때만 `X` = 나누기** 로 바꿨다.
- 모드가 꺼져 있으면 `X` 는 **예전과 똑같이** 상자 모드 토글이다(`numKey()` 가 모드 켜짐일 때만 키를 먼저 가져가고, 기존 `case "x"` 에도 `if (S.numMode) break;` 방어를 넣었다).
- 두 모드는 **동시에 켜지지 않는다**: 번호 편집 모드를 켜면 상자 모드가 꺼지고 체크박스가 잠긴다. 상자 모드를 켜려 하면 «번호 편집 모드를 먼저 끄세요 (K)» 라고 알린다.
- 새로 쓴 키: `K`(모드), `J`(번호 레이어), `D·M·X·N`(편집 4가지, 모드 켜짐일 때만). `D` 는 모드가 꺼져 있으면 예전처럼 «차이 보기» 토글이다.

## ④ 가정한 것 (❌ = 근거 없는 우리 판단)

1. ❌ **조작 순서**를 지시서 표 그대로 «고르고 나서 키»(클릭→`D`, A·B 클릭→`M`) 로 했다. 클릭만으로 바로 지워지지 않으므로 잘못 눌러 지워질 위험이 적다. 도구 단추를 누르면 그 키를 쓰라는 안내가 뜬다.
2. ❌ **연결성분은 4-이웃**. 1px 선으로도 확실히 갈라지게 하려는 선택이다(8-이웃이면 대각선 1px 선이 안 갈린다).
3. ❌ **나누기에서 «한쪽»** 은 «선의 진행 방향 기준 외적이 음수인 쪽 조각들» 로 정했다. 조각이 여럿인 번호도 선 기준으로 갈라진다.
4. ❌ **나누기 성공 조건**을 «조각 수가 늘었다 + 선 양쪽에 조각이 있다» 둘 다로 했다. 하나만 보면 선이 열매를 살짝 스쳐도 새 번호가 붙는다.
5. ❌ 새 번호는 **그 사진의 최대+1**. **[사이클3 정정]** «빈 번호를 다시 쓰지 않는다» 는 절반만 맞다 — 같은 편집 세션 안에서는 화면이 `S.instMax`(커질 때만 갱신)를 쓰므로 지운 번호를 다시 쓰지 않지만(55 를 지워도 다음은 56), 저장한 뒤 사진을 다시 열면 파일의 최대+1 이라 **빈 번호가 다시 쓰일 수 있다**(번호가 겹치는 일은 없다). 지시서 §2 의 «번호는 1부터 연속일 필요 없음» 에 맞춘다.
6. ❌ 되돌리기 **40단계**(요구는 10단계 이상). 바뀐 화소만 기록하므로 메모리 부담이 작다.
7. ❌ 번호 레이어 진하기 기본 **60%**, 번호 글자 기본 **켬**. 기존 «원본 GT»·«알마다 다른 색» 체크박스는 **건드리지 않았다**(사용자가 보던 상태를 말없이 바꾸지 않으려고). 두 레이어가 겹쳐 지저분하면 «원본 GT» 를 끄면 된다.
8. ❌ «번호 편집 대상» 정렬에서 목록을 최대 **30쪽(15,000장)** 까지 모은다. 지금 가장 많은 포도 2,500장에 넉넉하다.
9. ❌ 번호 편집 모드에서 «수정본 저장»(0/255) 단추도 잠갔다. 지시서 §3-1 의 «저장 규칙이 꼬인다» 를 그대로 따랐다.

## ⑤ 남은 것 · 2차 검수가 재현할 절차

### 확인 못 한 것 (정직하게)

- **실제 브라우저에서 눈으로 본 것은 없다.** 마우스 사건 처리·캔버스 그리기(번호 글자 위치, 점선 상자, 잠금 표시)는 함수 단위 시뮬레이션과 코드 검토까지만 했다. 사람이 크롬에서 한 번 열어 봐야 한다.
- 번호 편집 모드에서의 **되돌리기 단추(`#numundo`)·모드 토글·목록 정렬**은 DOM 이 필요해 node 로 돌리지 못했다(순수 함수 부분만 시험했다).
- **블루베리 초벌(seed) 번호로 실제 편집·저장**은 하지 않았다(사과만 했다). `/api/instance_info` 로 `source=seed`, 번호 15~71개인 것만 확인했다(`Camera 1 Video (1)_1` 등 6장).
- 사진 여러 장을 연달아 편집할 때의 메모리 누적은 보지 않았다.

### 서버 쪽에 필요한 것 (⛔ 지시대로 건드리지 않고 적기만 함)

1. **`/api/revert_instances` 가 `instances_edited`·`instance_counts` 를 지우지 않는다.** 되돌린 뒤에도 `status.json` 에 «번호 편집함 · erase=1 merge=1 split=1 add=1» 이 남아(status 는 `unreviewed` 로 바뀜) 진행 집계가 틀어질 수 있다. 되돌릴 때 두 열을 지우는 것이 맞다.
2. **`/api/list` 에 `sort=insterr` 가 없어** 화면이 목록을 여러 쪽 받아 와 정렬한다(사과 3번 요청). 서버가 오류 CSV 를 읽어 정렬해 주면 요청 한 번으로 끝난다. 지금도 동작은 정확하다.
3. `/api/component` 를 «번호 마스크면 그 번호 전체를 반환» 으로 분기하는 §3-3 마지막 항목은 **필요하지 않았다**(화면이 번호 마스크를 직접 갖고 있어 클릭한 번호를 바로 안다).
4. §3-5 내보내기(`export/export_dataset.py --instances`)는 내 담당(화면 3파일)이 아니어서 손대지 않았다.
