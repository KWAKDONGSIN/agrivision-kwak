### (1) 확대/축소·이동 상태의 좌표가 원본 픽셀과 맞는가

`draw()` 는 `setTransform(dpr,…) → translate(S.view.tx, S.view.ty) → scale(S.view.s)` 이고 `toImg()` 는
`(clientX - r.left - tx) / s` 입니다. 두 식이 정확히 역함수인지, 휠 확대가 커서 밑 좌표를 보존하는지
`node` 로 수치 확인했습니다 (`sim.js`, 배율 0.03~30배 · 이동량 -1234.5~5000 조합).

```
$ node sim.js
A. toImg<->draw 역변환 최대오차(이미지px): 1.32e-11
B. 휠 확대 후 커서밑 좌표 이동(이미지px): 4.55e-13
```

→ 부동소수 오차 수준. `S.W`/`S.H` 는 `/api/item` 이 `Image.open(원본).size` 로 준 **원본 픽셀**이고
(`app.js:309`), `drawBoxes`·`hitBox`·`hitHandle` 는 모두 이미지 좌표계에서 계산하며 화면 크기(손잡이
`HANDLE`, 선 굵기)만 `/ S.view.s` 로 되돌립니다 — 규칙이 일관됩니다.

**단, 같은 스크립트의 «옮기기»(move) 재현에서 버그가 나왔습니다** (③-B1 참조).

```
C. move 모드 (화면 1px 씩 100회 드래그):
   배율  0.25x : 상자가 간 거리 400 px / 마우스가 간 거리 400.00 px
   배율     1x : 상자가 간 거리 100 px / 마우스가 간 거리 100.00 px
   배율     2x : 상자가 간 거리 100 px / 마우스가 간 거리  50.00 px   ← 두 배로 감
```

### B1. (확실) 확대 상태에서 상자를 옮기면 좌표가 어긋난다 — `app.js` `boxMouseMove`

원인: 마우스가 움직인 양을 **한 이벤트마다 반올림해서 누적**했습니다.

```js
const nx = Math.max(0, Math.min(S.W - w, b.xyxy[0] + dx));
b.xyxy = [Math.round(nx), …];
S.drag.px = x; S.drag.py = y;        // ← 버려진 소수가 회복되지 않는다
```

배율 s 에서 마우스 1화면픽셀 = 0.5/s 이미지픽셀이라, s≥3 이면 매 이벤트의 이동량(<0.5)이 반올림에서
전부 버려져 **상자가 전혀 움직이지 않고**, s=2 이면 0.5 가 매번 1로 올라가 **두 배로 움직입니다**.
`Math.round(nx+w)` 를 따로 반올림해 **옮기는 중에 상자 크기가 1픽셀 변하는** 문제도 같이 있었습니다.

고침: 잡은 순간의 상자 위치·크기와 마우스 위치를 `S.drag` 에 소수 그대로 저장하고, 매번 «처음부터의
전체 이동량» 으로 다시 계산합니다. 크기는 정수 `bw/bh` 를 더해 보존합니다.

확인:

```
$ node --check app.js   → 통과
$ node sim2.js
   배율 0.25x : 오차 0.00, 크기 100,100
   배율    1x : 오차 0.00, 크기 100,100
   배율    2x : 상자 50 px / 마우스 50.00 px  (오차 0.00, 크기 100,100)
   배율    3x : 상자 33 px / 마우스 33.33 px  (오차 0.33, 크기 100,100)
   배율   30x : 상자  3 px / 마우스  3.33 px  (오차 0.33, 크기 100,100)
모든 배율에서 오차 <=0.5px, 크기 보존 — 통과
```

(남는 0.33px 은 «정수 픽셀로 저장한다» 는 규칙상 불가피한 반올림 1회분이며 누적되지 않습니다.)
