# 구조 사이클 4 — 별도 검수

자기 시험을 재사용해 합격으로 세지 않았다. 지시서가 요구한 대화 이력 없는 새 에이전트(`/root/handoff_trial`, fork_turns=none)가 README만 받고 `codex_resume/handoff_trial/`에서 실행했다.

|---|---|---|---|

| 서버 실행 및 첫 전체시험 | 02:50:38 → 02:59:11, 8분33초 | 30분 | 통과 |

첫째·둘째 전체시험 각각 1,102 단정 통과/0 실패, rc0, suite 488초. 두 번째는 실제 POST /api/boxes 성공 응답에 handoff_probe=true를 넣는 연습이며 HTTP200/ok/n_boxes=1을 따로 확인했다. 저장 상자·status JSON에는 그 칸이 없었다. 부모도 최종 후보 API에는 해당 연습 칸이 없음을 재확인했다. 이 시험은 이후 추가한 데이터 소실 보호·전환 관문·ff.py 보호 이전 사본이다. 최신 후보 전체시험은 구조5가 맡는다.

발견과 문서 수정:
- 빠른 시작 예제의 PYTHONPATH가 외부 안전 장치를 지우지 않도록 기존 값을 이어 붙였다.
- 공개 저장소만으로는 로컬 데이터·팀 자료·백업 의존 전체시험을 재현할 수 없음을 명시했다.
- API 응답과 파일 형식을 실제 코드와 대조했다. status revision이 존재한다는 초안, 전부 무효인 상자와 빈 목록이 원래 구분됐다는 초안 등 잘못된 서술을 정정했다.
- 별도 AST 검사 결과 공개 함수113개 모두 설명/매개변수/반환 타입 표기 있음. 36개 서로 다른 route 주소 모두 README에 존재한다(표는 메서드를 나누어 37행). Any/긴 함수/JS 잔존은 숨기지 않았다.
- 별도 상자 API 검수 7조건: 유효+무효 혼합 입력, 완전히 무효인 세 종류, 연습 칸 미혼입, 이름 칸의 기존 처리, 명시적 빈 목록 되돌리기. 무효 세 종류 모두 기존 파일 sha256 보존.
- 검수기 첫 버전은 AI로 시작하는 표시 이름을 거절할 것이라고 잘못 가정해 실패했다. 코드는 표시 이름을 인증 수단으로 삼지 않는다. 원래 동작을 유지하며 그 가정을 철회했다. 실패 버전은 보존했다.

추가 독립 증거: 고정 입력·같은 절대경로로 이전/후보 내보내기를 실행했다. 네 과일×3장 합성 표본, 번호2개/상자2개, 원시 산출물60개 SHA-256 차이0. CSV 이름·시각·경로 칸도 제거하지 않았다. 기존 실제12장 기준선 검사를 보완하며 대체하지 않는다.
