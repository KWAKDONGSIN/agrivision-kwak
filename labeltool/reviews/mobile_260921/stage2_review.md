# 별도 검수

## 공격적 입력 검수

check_touch.py는 새 sandbox_touch 서버를 만들고 실제 등록된 touchstart/move/end/cancel에 합성 이벤트를 전달한다. 앱 내부 편집 함수를 시험에서 직접 대신 호출하지 않았다. 마스크 불변, 확대 중심 이동, 한손 상자 생성·삭제·복구·저장, 그리다 두손으로 바꿈, 손가락 하나를 먼저 떼기, 터치 취소, 번호 선택·삭제·큰 붓 추가·되돌림, 미완성 확정 차단을 검증했다. 판정 뒤 API를 다시 읽어 좋음/문제·작성자와 AI 칸 보존을 확인했다. 실제 묶음 확인창과 수정본 잔존 안내, 미저장 다음 경고도 확인했다. 24개 통과.

초기 실패 중 시험 자체의 원인은 자동 다음 사진 이동, 저장 요청 완료 전에 값을 읽은 것, 정상 안내창을 처리하지 않은 것, 마지막 사진에서 다음 경고를 기대한 것이었다. 각 로그를 남기고 해당 흐름을 바로잡았다. 실패를 삭제하거나 통과로 덮어 적지 않았다.

## 보통 사용 경로 검수

review_independent.py는 별도 Firefox 프로필, 360×740, /box 경로에서 WebDriver 실제 포인터로 목록20번째 사진을 열었다. 첫 구현은 scrollY738이 남아 사진이 사라졌다. 변경 후 맨 위로 복구하고 고정 이전/다음 단추를 실제 클릭했다. 전문가 모드의 목록·편집·현황·데이터 정리와 처음 안내까지7개 통과했다. 구현 시험의 단순 함수 대조와 다른 경로다.

## 코드 대조

서버 변경은 core/auth.py의 로그인 CSS뿐이다. API·저장·판정 함수를 바꾸지 않았다. mobile.js의 하단 단추는 기존 단추를 누르고 번호 적용도 기존 numKey 처리를 재사용한다. 미완성 번호 되돌림은 기존 Escape 처리다. PC 숨김 규칙과 820px 경계, touch-action:none, passive:false, 안전영역 여백을 확인했다.

판정은 모바일 기능 검수 통과, 전체 회귀와 화면 HTML 기준선 대조를 배포 조건으로 유지한다.
