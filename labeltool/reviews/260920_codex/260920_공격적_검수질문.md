# 최종 공격적 검수 질문

구조5 이후 새 관점에서 다음 주장을 반증한다. 먼저 의심을 세우고 실제 응답·파일을 확인한다.

1. strict 기준선 실패를 새 기준선/정규화로 숨기고 운영을 재시작한 것은 아닌가?
2. 오류 입력이 저장된 상자·사람 확정을 지우는가? 유효 일부와 전부 무효를 구분하는가?
3. 브라우저 시험이 실서버로 자동 접속할 수 있는가? 남의 PID를 종료하는가?
4. 사람 확인·독립 팀원·개수 지표·논문143편을 과장하는가? 데이터 분모124/125/4070/4071을 섞는가?
5. API/CSV 비교가 이름/시각을 지워 데이터 손실을 못 보는가? 독립 raw 증거는 무엇인가?
6. README와 실제 route·스키마·전역·장함수 제한이 일치하는가?
7. 보호 수정이 유효 저장·명시적 빈 목록·출처 판정을 회귀시켰는가?

자기 작업의 성공 로그만 인용하지 말고 최소 한 경로를 새로 재현한다. 조치와 미결을 구분하고 이번 범위가 아닌 기능은 임의로 추가하지 않는다.
