# Codex 최종 공격적 검수

구조5 종료 뒤, 기존 자기 시험을 쓰지 않고 `codex_resume/final_attack.py`로 이전/최신 코드의 새 사본을 만들었다. 합성 사진을 쓰고 실제 Flask 요청·저장 파일 SHA를 관측했다.

## 채택할 지적

1. **운영 전환 조건 미충족.** 단정1124/0은 전체합격이 아니다. 원래 기준선6칸 실패를 추가 관문 성공으로 덮으면 안 된다. 구조5의 재시작 보류를 지지한다.
2. **상자 데이터 소실 보호는 필요하고 후보에서 작동한다.** `boxes:[null]`은 이전판HTTP200과 기존파일 변경, 후보400과 바이트 보존이었다. 숫자 항목 `[3]`도 후보400·보존. 잘못된 자료가 명시적 빈 목록과 혼동되던 길을 별도 입력으로 재현했다. 운영에는 아직 보호가 없다.
3. **비유한 좌표 입력에500이 남는다.** Infinity/NaN을 파서가 받아들인 뒤 round에서 예외가 난다. 이전·후보 모두500이며 기존 파일은 보존한다. 비표준 JSON 수치 입력에 대한 오류처리 결함으로 기록한다. 새 회귀나 데이터 소실은 아니므로 «동작 무변경, 비소실 버그는 목록» 지시에 따라 이번에 고치지 않는다.
4. **시험 수치·논문 범위를 부풀리면 안 된다.** 143편은 검색 대상 목록이지 전체 정독 증거가 아니다. 35건에는 시험 기대값1건이 포함되고 서로 다른 검수군 숫자를 고유 결함수로 합치면 안 된다. 최종 폰용 문서에서 바로잡는다.
5. **지표 분모·출처를 유지해야 한다.** 복숭아124장0.31과 옛125장0.30, 정본v3 4071장과 새시험4070장을 분리한다. 팀원 두 폴더는 독립 비교가 아니고, 정답 마스크 후처리 수치를 사진 예측 모델 성능이라 부르면 안 된다.
6. **구조목표 일부와 운영/후보 차이를 명시해야 한다.** window5개·긴함수3개·역호출·Any가 남고, 운영에는 이번 보호수정이 없다. 후보와 운영이 완전히 같다는 주장을 금지한다.

## 기각 또는 범위를 좁힌 주장

- «같은 이름이 AI로 시작하면 모든 저장API가 거절한다»는 주장은 틀리다. 이전/후보 모두 /api/status400, /api/boxes200이다. 소스 주석과 rules도 status에서만 막는 기존 결정을 명시한다. 이름은 신원 인증 수단이 아니며 이번 구조 버그로 분류하지 않는다.
- «CSV 이름/시각을 지워도 산출물 원시 동일이 증명됐다»는 말은 원래 기준선만으로는 성립하지 않는다. 별도 고정입력 내보내기60파일 원시sha, 실제12장API24응답 원시바이트 증거가 추가되어 그 한정 범위의 동일성은 인정한다.
- «ff.py는 여전히 주소 없이 실서버로 간다»는 주장은 최신 후보에 대해 기각한다. Popen을 실패하도록 대체한 새 검사에서 대상 누락이 프로세스 생성 전에 RuntimeError로 끝났다. 운영 scripts/ff.py에는 아직 반영 전이다.

결론: 구조5의 부분달성·운영전환보류를 유지한다. 비유한 좌표500과 동시편집/확정이력 같은 기존 미결은 후속 목록으로 남긴다. 공유 서버나 원본 데이터에는 쓰지 않았다.
