결론: 아래 8가지 관습을 도입하면 반복 검수 속도와 정확도를 크게 개선할 수 있습니다. 효과 순서대로 나열했습니다.

1. **도구 단축키 (B, E, G, L 등) – 포토샵**
2. **화살표 키로 이전/다음 이미지 이동 + 평결 자동 저장 – 윈도우 사진 뷰어·탐색기**
3. **주석 가시성 빠른 전환 (H 키) – 포토샵 레이어 눈 아이콘**
4. **클래스 선택 스포이트 (Alt+클릭) – 포토샵 스포이트 도구**
5. **자석 올가미(가장자리 스내핑 폴리곤) – 포토샵 Magnetic Lasso**
6. **Marquee 줌 (Ctrl+Space+드래그) – 포토샵**
7. **고정 배율로 빠르게 점프 (Ctrl+1 100%, Ctrl+2 200% 등) – 포토샵·윈도우 사진 뷰어**
8. **다시 실행(Redo, Ctrl+Y) – 포토샵·그림판·윈도우 기본**

추가로, 장시간 검수 중 데이터 손실과 잘못 저장을 막는 안정성 장치 3가지를 별도로 제안합니다.

---

### 8개 UI 관습 상세 설명

#### 1. 도구 단축키 (B: 붓, E: 지우개, G: 자동채움, L: 다각형 등)
- **어느 프로그램 관습인가:** 포토샵 등 모든 프로페셔널 편집 도구  
- **현재 불편한 점:** 도구 전환을 위해 매번 왼쪽 도구상자로 마우스를 이동해야 하며, 수백 장의 마스크를 편집할 때 마우스·시선 이동이 누적되어 피로와 속도 저하 발생.  
- **순수 JS/CSS 구현:** `keydown` 이벤트에서 `e.key`에 따라 해당 도구 버튼(`id='brush-btn'` 등)의 `.click()`을 호출. 입력 필드에 포커스가 있을 때는 무시하여 오작동 방지.

#### 2. 화살표 키로 이전/다음 이미지 이동 + 평결 자동 저장
- **어느 프로그램 관습인가:** 윈도우 사진 뷰어/파일 탐색기에서 좌우 화살표로 사진 탐색  
- **현재 불편한 점:** 검수 후 하단 판정 줄의 버튼을 마우스로 클릭한 뒤, 다시 마우스로 ‘다음 이미지’ 버튼을 눌러야 하므로 이미지 한 장 넘기는 데 여러 번의 클릭과 시선 분산이 생김.  
- **JS/CSS:** `keydown`에서 `ArrowRight`, `ArrowLeft` 처리. 현재 평결 상태를 저장하고 다음 이미지 로드 사이클 함수 호출. 판정과 다음 이동을 하나의 키로 결합 가능(예: 오른쪽 화살표 = 승인 후 다음).

#### 3. 주석 가시성 빠른 전환 (숨기기/보이기 토글)
- **어느 프로그램 관습인가:** 포토샵에서 레이어 눈 아이콘 또는 `\`키로 Quick Mask 토글  
- **현재 불편한 점:** 마스크와 원본을 비교 검증할 때 툴바에서 주석 레이어를 켜고 끄는 동작이 필요해 흐름이 끊김. 장시간 반복 시 사소한 클릭이 많은 시간을 소모.  
- **JS/CSS:** `keydown` H 키(또는 `~`)에 주석 캔버스/컨테이너의 `display` 속성을 `none`/`block`으로 토글. CSS로 `transition` 없이 즉시 전환.

#### 4. 클래스 선택 스포이트 (Alt+클릭)
- **어느 프로그램 관습인가:** 포토샵에서 Alt 키를 누르면 붓 도구가 스포이트로 변함  
- **현재 불편한 점:** 여러 클래스(과실 부위, 꼭지 등)를 구분하며 편집할 때 올바른 클래스 버튼을 찾아 클릭하는 일이 빈번하게 발생. 시선 이동과 인지 부하를 유발.  
- **JS/CSS:** 캔버스 `click` 이벤트에서 `e.altKey`를 확인. 클릭 지점의 마스크 픽셀 데이터를 읽고 미리 정의된 색상→클래스 매핑으로 활성 클래스를 변경. 현재 붓 도구에 자동 반영.

#### 5. 자석 올가미 (가장자리 감지 폴리곤 스내핑)
- **어느 프로그램 관습인가:** 포토샵의 Magnetic Lasso 도구  
- **현재 불편한 점:** 수동으로 폴리곤 점을 찍어 과일 경계를 수정할 때 미세하게 경계를 따라가기 위해 확대·축소를 반복하며 시간이 오래 걸리고 정밀도가 떨어짐.  
- **JS/CSS:** 다각형 툴 활성 시 `mousemove`에서 마우스 주변 10px 반경의 이미지 픽셀 그래디언트(Sobel 등)를 계산하여 가장 강한 에지 지점으로 후보 정점을 자동 이동. 스냅 반경 안에 들어오면 점이 찰칵 붙는 시각 피드백을 원형 오버레이로 표시. (드래그 성능 유지를 위해 `requestAnimationFrame` 사용)

#### 6. Marquee 줌 (Ctrl+Space+드래그로 영역 확대)
- **어느 프로그램 관습인가:** 포토샵에서 `Ctrl+Space`를 누르고 드래그하여 확대할 사각형 지정  
- **현재 불편한 점:** 휠로 단계적으로 확대/축소하고 Space 드래그로 이동하는 기존 방식은 특정 좁은 영역을 빠르게 확대하여 검사하려 할 때 여러 번의 동작을 요구함.  
- **JS/CSS:** `Ctrl+Space` 조합 감지 시 커서를 돋보기로 변경. `mousedown`부터 `mouseup`까지 임시 캔버스나 `div`로 선택 사각형을 그림. 마우스 놓으면 선택 사각형이 화면에 꽉 차도록 `transform` scale과 translate 계산하여 한 번에 적용.

#### 7. 고정 배율로 빠르게 점프 (100%, 200% 등)
- **어느 프로그램 관습인가:** 포토샵 `Ctrl+1` (100%), `Ctrl+2` (200%), 윈도우 사진 뷰어 `Ctrl+0` (맞춤)  
- **현재 불편한 점:** 휠 줌만으로는 1:1 실제 픽셀뷰나 정확한 200% 배율을 재현하기 어려워 경계 픽셀을 정확히 확인할 때마다 불필요한 조정이 필요함.  
- **JS/CSS:** `Ctrl+1` → `scale = 1`, `Ctrl+2` → `scale = 2`로 설정하고 현재 캔버스 중심이 유지되도록 pan 값 재계산. 숫자 키에 다중 배율 매핑 가능. 동시에 배율 표시 UI 짧은 업데이트.

#### 8. 다시 실행(Redo, Ctrl+Y)
- **어느 프로그램 관습인가:** 포토샵(`Ctrl+Shift+Z`), 윈도우 그림판(`Ctrl+Y`), 거의 모든 편집기  
- **현재 불편한 점:** 지우개나 붓으로 편집 후 `Ctrl+Z`로 너무 많이 되돌리면 실수로 필요한 수정까지 잃어버리며, 재실행이 없어 수동으로 다시 작업해야 함. 이는 마스크 검수 중 편집 오류를 복구하는 데 큰 리스크.  
- **JS/CSS:** Undo 시 되돌린 액션을 `redoStack`에 저장. `Ctrl+Y` 또는 `Ctrl+Shift+Z` 이벤트에서 `redoStack.pop()`으로 복원 로직 실행. 붓/채움/폴리곤 등 모든 조작에 대해 Redo 커맨드 패턴 구현.

### 장시간 검수 안정성 장치 3가지

1. **주기적 임시 저장(자동 초안 저장)**  
   - 60초 간격 혹은 편집 액션 스택이 쌓일 때마다 현재 이미지의 마스크 상태를 서버로 비동기 전송하여 초안(draft)으로 저장. 탭이 예기치 않게 종료되어도 마지막 초안에서 복원할 수 있도록 한다.  
   - 구현: `setInterval`로 `localStorage`에 메타데이터 + 이미지 ID와 함께 직렬화 상태를 쓰고, 네트워크 가능 시 서버 `PUT` 호출.

2. **저장되지 않은 변경 사항 이탈 방지**  
   - 사용자가 검수 중 실수로 브라우저를 닫거나 뒤로 가기를 누르지 않도록 `beforeunload` 이벤트에서 “저장되지 않은 변경 사항이 있습니다.” 경고창을 띄운다. 검수 완료 후 최종 저장 시 플래그를 해제한다.  
   - 구현: 편집 시 `isDirty = true` 플래그 설정. `window.addEventListener('beforeunload', (e) => { if (isDirty) e.returnValue = '...'; })`.

3. **이중 확인 제출(판정 제출 전 검토 및 확인)**  
   - 판정 줄의 ‘제출’ 버튼을 누르면 팝업이나 모달로 최종 마스크 미리보기와 함께 “정말로 이 검수를 마치겠습니까?” 확인 단계를 추가한다. 단축키 실수로 즉시 제출되는 것을 막고, 3초 후 자동 승인 없이 반드시 클릭하게 한다.  
   - 구현: 기존 판정 버튼 클릭 시 `e.preventDefault()` 후 모달 표시, 확인 버튼만 최종 저장+이미지 전환 트리거. 단축키를 통한 제출은 이 모달을 먼저 띄우게 매핑.

모든 제안은 기존 단축키·id 변경 없이 추가 이벤트 리스너와 CSS 클래스 조작만으로 순수 JS/CSS로 구현 가능하며, 추가 라이브러리는 불필요합니다.
