# 자문 요청 — 웹 라벨링 툴의 «사용자 편의»를 그림판·포토샵·윈도우 프로그램 수준으로 끌어올리기

## 누가 쓰는가
대학 연구실 학부생·대학원생 4~6명. 컴퓨터를 아주 잘 다루지는 않는다.
과일 사진(사과·블루베리·포도·딸기) 약 4,800장의 라벨(칠한 영역 마스크 / 바운딩 박스 / 열매 번호)을 눈으로 확인하고 고친다.
하루에 수백 장을 본다. 반복 작업이라 **손이 덜 가고 실수가 안 나는 것**이 제일 중요하다.

## 무엇으로 만들었나
Flask + 순수 JavaScript(프레임워크 없음) + `<canvas>` 한 장. 새 의존성 추가 불가.
소스: `/data/project/2026summer/platform/work/kwak_dongsin/260916_라벨링툴/app/`
- `static/index.html` (화면 뼈대), `static/style.css`, `static/mobile.css`
- `static/js/` — main.js, view.js(그리기·확대·이동), mask.js(붓), boxes.js(상자), counts.js·instances.js(번호),
  keys.js(단축키), list.js(목록), easy.js(쉬움 모드), tour.js(안내), api.js, state.js, export.js
- 서버: `app/server.py`, `app/api/*.py`, `app/core/*.py`, `app/domain/*.py`

## 이미 있는 것 (중복 제안 금지)
- 그림판식 배치: 위 한 줄 · 왼쪽 도구 상자 · 가운데 캔버스 · 오른쪽 접힌 패널 · 아래 판정 한 줄
- 도구: 붓 B / 지우개 E / 다각형 채우기 P / 빼기 O / 자동채움 F / 자동지움 G / 이동(팬)
- 붓 굵기 슬라이더와 `[` `]` 키, 되돌리기 Ctrl+Z(마스크 20단계·번호 40단계), 마스크만 다시하기 Ctrl+Y
- 휠 확대·축소, 스페이스+드래그 이동, 0 키 화면 맞춤, 확대 ＋/－/맞춤 단추 3칸
- 오른쪽 버튼 드래그 = 지우개, 모든 단추에 풍선말(title)과 단축키 배지
- 쉬움 모드 / 전문가 모드 전환(브라우저가 기억), 처음 사용자 안내 투어(? 키), 사용법 페이지
보안 관련 값·설정 세부는 공개본에서 생략했습니다.

## 물어보는 것
그림판(MS Paint), 포토샵, 윈도우 기본 프로그램(탐색기·메모장·그림판 3D), 그 밖에 널리 쓰이는
데스크톱 프로그램의 UI 관습 중에서 **이 툴에 아직 없는데 있으면 확실히 편해지는 것**을 골라 주세요.

각 항목을 이 형식으로, 효과가 큰 순서대로 최대 12개.
1) 이름 — 어느 프로그램의 어떤 관습인가
2) 지금 이 툴에서 무엇이 불편한가 (구체적인 상황 한 줄)
3) 어떻게 만들 것인가 — 건드릴 파일과 방법을 2~4줄로. 순수 JS·CSS로 가능한 범위
4) 위험 — 기존 단축키·요소 id·회귀 시험(HTML 기준선 대조가 있음)과 부딪히는가
5) 크기 — 작음(1시간 내) / 중간 / 큼

## 반드시 지킬 제약
- 요소 id, 기존 단축키, 서버 API 규칙을 바꾸면 안 된다(회귀 시험 1,199개와 HTML 기준선이 걸려 있다)
- 새 라이브러리·CDN·빌드 도구 금지. 순수 JS/CSS만
- 화면을 통째로 새로 만드는 제안 금지. 지금 구조 위에 얹는 것만
- 초보자가 기본으로 쓰는 «쉬움 모드»를 더 복잡하게 만들면 안 된다
