2. 만든 것과 쓰는 법

그림판식 라벨링 툴

사진 위에 마스크를 칠하고, 상자를 그리고, 열매 번호를 고칩니다. 원본만 보기, 마스크만 보기, 겹쳐 보기를 고를 수 있습니다. 수정본은 시안색입니다. 원본 자료는 읽기만 하고 사람이 고친 것은 별도 파일에 저장합니다.

잘못 칠한 부분은 E 지우개로 지웁니다. G 자동지움은 덩어리를 지웁니다. 전체를 비우려면 오른쪽 더 보기의 전부 지우기를 씁니다. 저장 전 Ctrl+Z로 되돌릴 수 있습니다. 번호는 번호 모드에서 선택하고 D를 누릅니다.

사람 확정과 내보내기

AI 판정과 사람 확정은 다른 칸입니다. 마스크·상자·번호 확정도 서로 구분합니다. 이름 칸에 본인 이름을 적고 확인합니다. 이름 칸은 서명 인증 기능은 아닙니다. 데이터 정리 탭은 기본적으로 사람이 확정한 결과만 새 날짜 폴더로 내보냅니다.

2026-09-19 22:55에 익명으로 복숭아 문제 있음 확정 한 건이 생겼습니다. 이를 학습에 쓸 정상 확정 한 건으로 세면 안 됩니다. 옛 초안의 '아무도 확정하지 않았다'도 틀립니다.

상자와 개수

/box에서 상자를 편집합니다. 박성문·임성후 폴더의 상자를 초벌로 읽습니다. 두 폴더의 4,823개 파일 내용이 같아서 서로 독립된 결과의 비교로 해석하지 않습니다. 상자와 번호의 개수 및 출처를 화면에 보여 주고 counts.csv 12개 칸으로 내보냅니다. 두 가지 사람 확정 개수가 다르면 자동으로 하나를 고르지 않고 충돌로 표시합니다.

상자 0개를 직접 저장하는 것은 해당 상자 수정본을 되돌리는 뜻입니다. 이번 후보에서는 잘못된 상자만 들어온 요청을 400 오류로 막아, 기존 상자가 함께 사라지지 않게 했습니다. 이 수정은 운영 서버에 아직 반영하지 않았습니다.

통합 데이터셋

보존 중인 정본은 datasets_merged_260918_v3입니다. 사진 4,071장: 사과 429, 포도 2,403, 복숭아 125, 블루베리 1,114장입니다. manifest.csv는 빠진 사진과 이유까지 담는 목록표입니다. 새 빌드에서 복숭아 flag 확정 한 장을 빼면 전체 4,070장, 번호 마스크는 1,667장이 됩니다. 이번 구조 정리의 시험 빌드와 보존 중인 v3를 혼동하지 않습니다. v3 원본은 덮어쓰지 않았습니다.

개수 정확도의 뜻

3. 논문 대조와 정정

기존 검수는 PDF 143편을 검색 대상에 넣고, 근거 대조표 28칸과 인용 51건을 확인했습니다. 143편 전체를 처음부터 끝까지 정독했다는 뜻은 아닙니다.

5. 구조 정리와 이어받기

대화 이력 없이 README만 받은 새 에이전트가 규칙을 찾는 데7초, 서버 실행과 전체시험에8분33초, 응답 수정과 재시험에8분11초가 걸렸습니다. 세 기준을 모두 통과했고 두 전체시험은 각각1,102/0이었습니다. 처음 읽기부터 두 번째 시험 종료까지 합쳐도17분15초입니다.

최신 후보 전체시험은 단정1,124 통과/0 실패,527초였습니다. 그러나 원래 엄격 기준선에서 화면 파일의 지문6칸이 달라 전체 명령은 실패입니다. 추가 고정해시 검사가 통과해도 이 실패를 지우지 않았습니다. 운영 코드 교체와 재시작은 보류했습니다.

독립 비교에서 기존·새 화면의 12장 스크린샷이 바이트까지 같았습니다. API 64요청과 저장 결과 47항목은 시각 등 변동값을 제외한 비교에서 같았습니다. 고정 입력으로 내보낸 파일 60개는 시각·이름·경로를 지우지 않고 SHA-256이 같았습니다.

긴 함수 3개, JS 전역 연결 5개, 화면 함수의 역방향 호출, 단축키 표와 분기의 중복은 남았습니다. 구조 목표가 모두 완성됐다고 쓰지 않습니다. 현재 시험 환경 밖의 동작까지 증명한 것도 아닙니다.

7. 사용자가 할 일과 확인할 질문

직접 할 일

  1. 이름을 적고 복숭아부터 실제 사진을 보며 확정합니다.
  2. 사람 확인 체크리스트 18항목을 크롬에서 확인합니다. 자동 Firefox 시험으로 대신할 수 없는 사용성 확인입니다.
  3. 같은 사진을 여러 사람이 동시에 고치지 않도록 과일·구간을 나눕니다. 오래된 탭의 저장을 막는 기능은 없습니다.
  4. 원본과 시험 잔재를 바로 삭제하지 않습니다. 보관 여부는 목록을 보고 판단합니다.
  5. 필요한 논문 원문과 출판판 쪽 번호를 확인합니다. 팀 카톡 초안은 저장했지만 자동으로 보내지는 않았습니다.

교수님과 팀원에게 확인할 것

  1. 가려진 열매 부분까지 라벨할지, 보이는 부분만 라벨할지 출처별로 통일할 기준.
  2. 포도 한 송이의 정의. 답이 나오기 전에는 포도 번호 초벌을 끈 채 유지.
  3. other 분류를 trunk로 바꿀지와 학습에서의 처리.
  4. 낙과 제외 권고와 사람이 고쳐야 할 사진 범위.
  5. 임성후 폴더가 독립 산출물인지, 동일한 두 상자 출처를 어떻게 표시할지.
  6. 복숭아 추정 번호 마스크의 사용 동의와 블루베리 정답 상자 마련.

재학습 모델·최소 확정 장수·촬영 단위 분할은 기존 연구 계획의 미결입니다. 이번 작업에서 임의로 정하지 않았습니다.
