# 교수님 실험 설계 — 쉬운 말로

## 0. 한 문장

"헤더 12개 × 백본 12개 = 144개 조합을, 데이터의 20%로 먼저 거르고, 나머지 80%에서 전부 한 번 + 유망한 것만 다섯 번 평가한다."

- 파일럿 20%는 **본실험에 절대 다시 안 쓴다.** 고르는 데이터와 평가하는 데이터를 완전히 분리하기 위해.
- 같은 나무·같은 영상·연속 프레임은 같은 쪽에 둔다(블루베리 = Camera N Video (M), 사과 = 촬영 시퀀스). 포도·복숭아는 그룹 정보가 없어 장 단위.

- 회전 규칙: 시험 fold t, 검증 fold t+1(순환), 나머지 2개로 학습. 그래서 모든 fold 가 시험 1번·검증 1번 쓰인다.

## 3. 단계 (앞이 얼기 전에 뒤를 얼리지 않는다)

```
① 12×12 동결 + 144조합 스모크 ........ ✅ 2026-09-08 (144/144 PASS)
② 20/80 분할 + 파일럿 4분할(v3) hash .. ✅ 2026-09-11
③ 공통 학습 설정 고정 (loss·LR·seed) ... 🟡 일부 미정 (weight decay·warm-up·update 예산 등)
④ C1  대표 2×2 × 4데이터셋 × 3fold, 300ep = 48런 ... ✅ 완주 (이력; 교수님 문서 표기 2026-09-07 완료, 파일 시각 09-08 09:46)
④′ 파일럿0 대표 2×2 × 4데이터셋 × 4회전, 800ep = 64런 ... ▶ v2 재실행 중 (09-13 00:11 시작, 09-13 12시 기준 8/64 완료, 완주 예상 09-14(월) 13:00~16:00, 런당 부대시간 14분·조합별 실측 속도 반영)
⑤ validation process 동결 (조기종료 규칙·체크포인트 규칙) ... ⏳ 파일럿0 끝난 뒤
⑥ P  144조합 × 4데이터셋 × 4회전 = 2,304런 → C 동결 ... ⏳
⑦ frozen/ 에 설정·코드·가중치·분할 hash 기록 ... ⏳
      ↓ 본실험
M1  144조합 전부, 학습 M2∪M3∪M4∪M5 → 시험 M1 = 576런
M2~M5  C(12~23개)만 나머지 4-fold 추가 = 16×|C| = 192~368런
```

| 파일럿0 | 800 epoch 긴 궤적에서 검증·시험이 어떻게 움직이나, 자원은 얼마나 드나. **09-13 결정 31: 구간별(100~800) 최고 검증 체크포인트를 전체영상 슬라이딩으로 평가해 "몇 epoch 예산이면 충분한가" 판정** | 🟡 파일럿 문서 §1 표는 아직 "미정"(낡은 듯) · 결정 31 로는 epoch 예산 + 조기종료·체크포인트 규칙 | 64런 (v2 재실행 중) |

## 4. C1 이 알려준 것 (실측; 교수님 문서 표기 2026-09-07 완료, 마지막 체크포인트 파일 시각 09-08 09:46)

- 규칙 두 개를 같은 궤적에 사후 적용: standard = 80 epoch 지나고 40 epoch 안 좋아지면 멈춤 / fast = 40 지나고 10.
- fast 가 standard 보다 놓친 IoU(regret): 중앙값 0.0085, 평균 0.032, **최악 0.604**(복숭아 VWFormer×ResNet-50 fold2: fast 42ep 에 멈췄는데 standard 는 175ep 에서 훨씬 좋아짐).
- 데이터셋별 중앙값: 포도 0.003 · 사과 0.007 · 블루베리 0.017 · 복숭아 0.030. 작은 데이터셋일수록 늦게 좋아진다.
- standard 는 평균 164 epoch, fast 는 63 epoch 에서 멈춤. 런당 1.72시간, 합계 82 GPU시간.
- 교수님이 이걸로 규칙을 확정하지 않고 **파일럿0(800 epoch)를 추가**하셨다. 300 epoch 로는 후기 개선을 다 못 본다고 판단하신 것으로 보인다(❌ 내 추정, 문서엔 "사용자 지시"라고만 있음). 그리고 09-13 에 파일럿0 를 **구간별 체크포인트를 남기는 v2 로 재실행**(결정 31)하셨다. 이유는 문서에 명시: "몇 epoch 예산까지 하면 성능이 유지되는가"를 프로토콜 시험 지표(전체영상 슬라이딩)로 판정하려면 구간별 최고 검증 모델의 가중치가 필요한데 첫 판은 best·final 2개만 저장했기 때문.

**발표 때는 "v2 실행 중, 포도 MiT-B2 만 8런 끝났고 100 epoch 뒤 이득이 0.006 이하, 결론은 완주 후"로 말할 것.**

## 6. P 선별 규칙 (결정 14~16)

- 144조합 × 4데이터셋 × 4회전 = 2,304런. 검증 fold 로 체크포인트 고르고, **시험 fold** 의 image-macro Dice 로 점수.
- 데이터셋마다 4회전 평균 → 4데이터셋 **동일 가중** 평균(포도가 점수를 지배하지 못하게).
- A = 헤더마다 1등 백본(12개), B = 백본마다 1등 헤더(12개), C = A∪B. 12 ≤ |C| ≤ 23. 동점은 ID 사전순.
- 효율(속도·메모리)은 점수에 안 넣는다(결정 20). 복숭아 순위 vs 나머지 3개의 Kendall τ 를 보고(결정 19).
- P 끝나면 C 를 잠근다. M1 결과 보고 바꾸지 않는다(결정 25).

## 7. 본실험과 승자 둘

- M1: 144조합 전부 같은 시험지(M1). "Full-grid winner" = 여기 1등.
- M2~M5: C 만 나머지 4 fold 추가 → C 는 5-fold OOF 완성. "Cross-validated winner" = 여기 1등 = **논문의 실무 최종 권장**.
- 둘이 다르면 분할 의존성·pilot→main 순위 변화·데이터셋 이질성·상호작용·C 의 M1 top-k 포착률을 보고.

## 8. 평가 방법 (06 문서)

- test 는 **전체 영상 슬라이딩 윈도우** 512, stride 384(25% 겹침), threshold 0.5 고정, TTA·후처리 없음. 지표는 영상 단위로 계산(image-macro Dice 주 지표).
- 센터크롭은 학습 중 검증(매 epoch)과 효율 측정에만 쓴다. 이유: 센터크롭은 과실의 75~77% 를 아예 못 본다(실측).
- 통계: paired 비교 + 다중비교 보정이 주. Friedman 은 보조, 블록 = 데이터셋 4개.
- 슬라이딩 윈도우 추론 코드(O-1)는 09-13 안내.md 기준 **"✅ 있음"** — `04_experiments/260911_파일럿0/코드/semseg/eval/sliding.py`(C0 전체영상 궤적에 사용). 단 `03_code` 에는 미반영. (09-12 판에 "0건"이라 쓴 것은 낡은 안내.md 를 본 것.) 내 브랜치 `kwak/slide-inference-0827` 과의 관계는 확인 필요.
