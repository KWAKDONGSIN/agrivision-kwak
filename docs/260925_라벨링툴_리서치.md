# 라벨링 툴 리서치 (R01) — 그림판에 넣을 기능 순위

## 범위와 한계
- 우리 논문·자료 폴더(`연구실 블루베리/01_*`, `03_*`)는 대부분 백본·헤더 벤치마크 논문이라 «라벨링 도구» 내용이 거의 없습니다. 관련 있는 것은 `03_참고논문_리뷰/260713_쉬운정리_라벨링선택_FewShot세포분할논문.pdf`(arXiv 2211.10244) 하나뿐입니다.
- 인터넷은 WebSearch·WebFetch 로 3건 검색 + 1건 열람만 했습니다(한도 절약). 논문 본문은 못 열었고 검색 요약과 CVAT 공식 페이지 내용에 의존했습니다. 수치는 그 출처가 말한 값이며 우리 데이터에서 잰 것이 아닙니다.
- 우리 그림판의 현재 기능은 `문서/260923_그림판툴_사용법.md` 와 paint.js 를 grep 한 것입니다. ✨ 는 점·네모·Shift 만 지원(`/api/sam` 에 x,y 또는 box).

## 조사에서 나온 것
1. **논문(내부)** — 정답을 달 사진을 무작위로 고르지 말고 AI 가 헷갈려 하는 사진부터 고르면 같은 예산으로 성능이 더 오른다(현미경 세포, 다른 방법들보다 나음). 블루베리는 야외 컬러라 그대로 통하는지는 직접 확인해야 함.
2. **CVAT** — SAM 2 를 이미지·영상 분할에 통합, SAM 2 Tracker 는 한 프레임에서 클릭하면 뒤 프레임까지 따라가며 칠함(원 SAM 프레임별 작업보다 8.4배 빠르다고 자체 발표). SAM 3 는 «라벨 하나 고르고 예시 하나 클릭 → 같은 종류를 한꺼번에 찾음». 한 장에 200개까지, 겹치고 빽빽하고 흐리면 성능이 떨어진다고 스스로 밝힘. 라벨은 «apple» 처럼 짧은 명사가 낫다.
3. **Label Studio** — SAM 2 를 ML Backend 로 연결, 영상용 VideoVector 태그. 우리는 이미 서버에 SAM 도우미가 있어 새로 얻을 것은 «연결 방식» 이 아니라 «상호작용 방식».
4. **과일 반자동 라벨링 논문(배 과수원, SAM 제로샷, 2025~26)** — 자동 라벨 + 사람 교정이면 한 장당 45초 vs 완전 수작업 157초(70%↑ 절감), 그렇게 만든 라벨로 학습한 모델과 수작업 라벨 모델의 성능 차이는 1% 미만. 색·둥근 정도로 마스크를 걸러 잎·가지를 버림.
5. **능동학습·라벨 교정 문헌(2025)** — 불확실한 사진부터 라벨링, 라벨 오류를 자동 표시해 사람이 확인하는 흐름(A²LC 등)이 주류. 자세한 수치는 열어 보지 못함.

## 결론 — `코드` 항목으로 올린 것 (5개, 상한 6 이하)
- C-A(1위) 비슷한 열매 한꺼번에 찾기. ✨ 도우미에 «자동 마스크 후보» 요청 추가 필요. 도우미(`ai_helper/sam_server.py`, GPU7)는 지금 한 번에 하나만 냄.
