# 교수님 실험 설계 — 쉬운 말로

## 0. 한 문장

"헤더 12개 × 백본 12개 = 144개 조합을, 데이터의 20%로 먼저 거르고, 나머지 80%에서 전부 한 번 + 유망한 것만 다섯 번 평가한다."

## 1. 2026-09-11 에 바뀐 것 (지난주 순서도와 다른 점)

| 항목 | 지난주(09-08) | 지금(09-11 이후) |
|---|---|---|
| 파일럿 안 나누는 법 | 3-fold (학습 2 / 검증 1) | **4분할** (학습 2 / 검증 1 / 시험 1) — 결정 29 |
| 회전 수 | 데이터셋당 3회 | 데이터셋당 **4회** |
| C1 (48런, 300 epoch) | 진행 중 → 완주 | 완주. 이제 **"이력"**(옛 3-fold라 새 설계와 직접 비교 안 함) |
| 새 단계 | 없음 | **파일럿0** = 대표 2×2 × 4데이터셋 × 4회전 = 64런, **800 epoch 완주** — 결정 30. 2026-09-11 17:27 시작 |
| P 선별 런 수 | 1,728 | **2,304** (144 × 4 × 4) |
| 전체 런 수 | 2,496~2,672 | **3,072~3,248** (파일럿0·C1 포함 3,184~3,360) |
| GPU 상태 | 8장 유휴 | 8장 전부 교수님 파일럿0 실행 중 |

왜 4분할로 바꿨나: 파일럿 안에서도 "체크포인트 고르는 데이터(검증)"와 "점수 재는 데이터(시험)"를 분리하려고. 3-fold 때는 검증 fold 하나로 둘 다 했다. 대신 회전당 학습 표본이 파일럿의 2/3 → 2/4 로 줄었다.

## 2. 데이터를 어떻게 나누나 (결정 12·29)

| 데이터셋 | 전체 | 파일럿 20% | 파일럿 회전당 학습/검증/시험 | 본실험 80% | M1~M5 한 조각 |
|---|---:|---:|---|---:|---:|
| 블루베리 | 1,195 | 239 | 119~120 / 59~60 / 59~60 | 956 | 191 |
| 사과 | 1,001 | 200 | 82~118 / 41~66 / 41~66 | 801 | 160 |
| 복숭아 | 125 | 25 | 12~13 / 6~7 / 6~7 | 100 | 20 |
| 포도 | 2,502 | 500 | 250 / 125 / 125 | 2,002 | 400 |

- 파일럿 20%는 **본실험에 절대 다시 안 쓴다.** 고르는 데이터와 평가하는 데이터를 완전히 분리하기 위해.
- 같은 나무·같은 영상·연속 프레임은 같은 쪽에 둔다(블루베리 = Camera N Video (M), 사과 = 촬영 시퀀스). 포도·복숭아는 그룹 정보가 없어 장 단위.
- 옛 실험(C0)에서 validation 으로 본 복숭아 23장·포도 250장은 그룹째 파일럿에 넣고 `prior_validation_exposure=true` 로 표시. 본실험에 안 들어간다.
- 분할 파일: `platform/04_experiments/260908_파일럿/protocol_splits/v3_seed3407/` (seed 3407). v2(3-fold)는 C1 이력용.
- 회전 규칙: 시험 fold t, 검증 fold t+1(순환), 나머지 2개로 학습. 그래서 모든 fold 가 시험 1번·검증 1번 쓰인다.

## 3. 단계 (앞이 얼기 전에 뒤를 얼리지 않는다)

```
① 12×12 동결 + 144조합 스모크 ........ ✅ 2026-09-08 (144/144 PASS)
② 20/80 분할 + 파일럿 4분할(v3) hash .. ✅ 2026-09-11
③ 공통 학습 설정 고정 (loss·LR·seed) ... 🟡 일부 미정 (weight decay·warm-up·update 예산 등)
④ C1  대표 2×2 × 4데이터셋 × 3fold, 300ep = 48런 ... ✅ 2026-09-08 완주 (이력)
④′ 파일럿0 대표 2×2 × 4데이터셋 × 4회전, 800ep = 64런 ... ▶ 실행 중 (2026-09-12 12시 기준 16/64 완료, 남은 약 29 GPU시간)
⑤ validation process 동결 (조기종료 규칙·체크포인트 규칙) ... ⏳ 파일럿0 끝난 뒤
⑥ P  144조합 × 4데이터셋 × 4회전 = 2,304런 → C 동결 ... ⏳
⑦ frozen/ 에 설정·코드·가중치·분할 hash 기록 ... ⏳
      ↓ 본실험
M1  144조합 전부, 학습 M2∪M3∪M4∪M5 → 시험 M1 = 576런
M2~M5  C(12~23개)만 나머지 4-fold 추가 = 16×|C| = 192~368런
```

### 각 단계가 "정하는 것" (파일럿 문서 §1 표)

| 단계 | 무엇을 정하나 | 성능 보고 골라도 되는 것 | 규모 |
|---|---|---|---|
| C0 | 코드·규칙 1차 점검 | 없음 | 옛 6런 × 200ep (완료) |
| C1 | fast 조기종료가 후기 개선을 놓치나 | 조기종료 규칙 | 48런 (완료, 이력) |
| 파일럿0 | 800 epoch 긴 궤적에서 검증·시험이 어떻게 움직이나, 자원은 얼마나 드나 | 🟡 **교수님이 아직 "미정"으로 두심** | 64런 (실행 중) |
| P | 144조합에서 C 를 고른다 | **C = A∪B 만** | 2,304런 |
| M1 | 144조합 공통 순위·주효과·상호작용 | 없음 | 576런 |
| M2~M5 | C 의 fold 안정성 | 없음 | 192~368런 |

## 4. C1 이 알려준 것 (실측, 2026-09-08 완주)

- 규칙 두 개를 같은 궤적에 사후 적용: standard = 80 epoch 지나고 40 epoch 안 좋아지면 멈춤 / fast = 40 지나고 10.
- fast 가 standard 보다 놓친 IoU(regret): 중앙값 0.0085, 평균 0.032, **최악 0.604**(복숭아 VWFormer×ResNet-50 fold2: fast 42ep 에 멈췄는데 standard 는 175ep 에서 훨씬 좋아짐).
- 데이터셋별 중앙값: 포도 0.003 · 사과 0.007 · 블루베리 0.017 · 복숭아 0.030. 작은 데이터셋일수록 늦게 좋아진다.
- standard 는 평균 164 epoch, fast 는 63 epoch 에서 멈춤. 런당 1.72시간, 합계 82 GPU시간.
- 교수님이 이걸로 규칙을 확정하지 않고 **파일럿0(800 epoch)를 추가**하셨다. 300 epoch 로는 후기 개선을 다 못 본다고 판단하신 것으로 보인다(❌ 내 추정, 문서엔 "사용자 지시"라고만 있음).

## 5. 파일럿0 가 지금까지 보여주는 것 (2026-09-12 12시, 포도 16런 완료분만)

| 조합 (포도) | best epoch (4회전) | 검증 Dice @best | 시험 Dice @best | 시험 Dice @800 |
|---|---|---|---|---|
| BackboneUNet × MiT-B2 | 288 / 145 / 331 / 345 | 0.946~0.958 | 0.942~0.955 | 0.945~0.957 |
| BackboneUNet × ResNet-50 | 498 / 661 / 574 / 113 | 0.942~0.956 | 0.940~0.954 | 0.941~0.953 |
| VWFormer × MiT-B2 | 151 / 547 / 465 / 224 | 0.946~0.958 | 0.941~0.956 | 0.945~0.956 |
| VWFormer × ResNet-50 | 685 / 412 / 327 / 576 | 0.944~0.955 | 0.942~0.949 | 0.936~0.947 |

읽는 법: 포도는 300 epoch 넘어서도 best 가 나오는 회전이 많다(498, 661, 685 등). 다만 best 시점과 800 시점의 시험 Dice 차이는 0.01 안쪽이라 "늦게 멈춰도 크게 손해는 없다". 이건 포도(500장)만이고, 복숭아(25장)·사과·블루베리는 아직 안 나왔다. **발표 때는 "실행 중이라 결론 없음"으로만 말할 것.**

## 6. P 선별 규칙 (결정 14~16)

- 144조합 × 4데이터셋 × 4회전 = 2,304런. 검증 fold 로 체크포인트 고르고, **시험 fold** 의 image-macro Dice 로 점수.
- 데이터셋마다 4회전 평균 → 4데이터셋 **동일 가중** 평균(포도가 점수를 지배하지 못하게).
- A = 헤더마다 1등 백본(12개), B = 백본마다 1등 헤더(12개), C = A∪B. 12 ≤ |C| ≤ 23. 동점은 ID 사전순.
- 효율(속도·메모리)은 점수에 안 넣는다(결정 20). 복숭아 순위 vs 나머지 3개의 Kendall τ 를 보고(결정 19).
- P 끝나면 C 를 잠근다. M1 결과 보고 바꾸지 않는다(결정 25).

## 7. 본실험과 승자 둘

- M1: 144조합 전부 같은 시험지(M1). "Full-grid winner" = 여기 1등.
- M2~M5: C 만 나머지 4 fold 추가 → C 는 5-fold OOF 완성. "Cross-validated winner" = 여기 1등 = **논문의 실무 최종 권장**.
- 둘이 다르면 분할 의존성·pilot→main 순위 변화·데이터셋 이질성·상호작용·C 의 M1 top-k 포착률을 보고.

## 8. 평가 방법 (06 문서)

- test 는 **전체 영상 슬라이딩 윈도우** 512, stride 384(25% 겹침), threshold 0.5 고정, TTA·후처리 없음. 지표는 영상 단위로 계산(image-macro Dice 주 지표).
- 센터크롭은 학습 중 검증(매 epoch)과 효율 측정에만 쓴다. 이유: 센터크롭은 과실의 75~77% 를 아예 못 본다(실측).
- 통계: paired 비교 + 다중비교 보정이 주. Friedman 은 보조, 블록 = 데이터셋 4개.
- 🔴 슬라이딩 윈도우 추론 코드는 교수님 planning 에서 "0건"으로 돼 있다(O-1). 내 브랜치 `kwak/slide-inference-0827` 에 구현이 있으니 확인 필요.

## 9. 아직 안 정해진 것 (발표 때 "미정"이라고 말할 것)

- 파일럿0 로 무엇을 결정할지(교수님 🟡 미정)
- weight decay · warm-up 길이 · 최대 update 수(복숭아 125 vs 포도 2,502 가 20배라 epoch 대신 update 로 맞출지) · seed 개수 · BN 처리 · gradient clipping · 실패 판정(NaN·OOM 재시작 횟수)
- 슬라이딩 중첩 결합(확률 평균 vs logit 평균) · inference batch size
- GPU 시간 재산정(C1·파일럿0 실측으로)

## 10. 논문에 쓰면 안 되는 말 (안내.md "잊으면 안 되는 것")

1. 후보 선정에 본실험 성능을 썼다 ✗ (CCASeg 때 실제로 적발됨)
2. C 를 줄인 이유가 "통계 검출력" ✗ → 계산량·축 대표성·설명 단순성
3. 144조합 M1 순위 = C 의 5-fold 순위 ✗ → 둘을 구분
4. "전체 데이터 5-fold CV" ✗ → "20% exclusive pilot; 144 on common M1 holdout; pilot-selected C with five-fold OOF"
5. "전수조사(exhaustive survey)" ✗ → candidate audit / scoping review

## 11. 이 설계가 답하려는 질문 넷 (교수님 02 §5)

1. 어떤 조합을 추천할 것인가
2. 좋은 백본은 디코더가 바뀌어도 좋은가 (주효과)
3. 성능이 부품의 합인가 궁합인가 (상호작용)
4. 최신 기법의 이득이 작고·많고·겹친 과실에서도 재현되는가
