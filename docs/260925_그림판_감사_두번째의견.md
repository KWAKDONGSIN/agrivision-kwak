# 그림판 감사(`260925_그림판_감사.md`)에 대한 두 번째 의견 — 빠진 것·과한 것

레인 r1(Claude Sonnet 5), 체크리스트 M02. 감사 문서의 주장을 코드(`app/static/paint/{index.html,paint.js}`, `app/api/{instances,photos}.py`)와 대조했다.
새로 재지는 않았다. 측정값은 f1 것을 그대로 믿고, «맞는지·순서가 맞는지·빠진 게 없는지» 만 봤다.

## 1. 코드로 확인된 것
- 접근성 속성: `index.html`·`paint.js` 에 `aria-`·`tabindex`·`role=` 가 **0건**. 팔레트 칸은 `<div class="sw">`(`paint.js` 677~680줄). 감사 §3 은 맞다.
- `/img` 는 이미 `max_age=3600, conditional=True`(`photos.py` 326~332줄). 그래서 사진 미리 받기는 `new Image().src` 한 줄로 브라우저 캐시에 들어간다.
- `/instances`·`/mask` 응답에는 캐시 헤더도 ETag 도 없다(`instances.py` 406~424줄). 감사 C07 진단(매번 다시 만든다)은 맞다.

## 2. 빠진 것
1. **C06·C07 의 안전 조건이 감사에 없다.** 미리 받은 `/instances`·`/mask` 를 메모리에 두면, 사람이 저장한 뒤 그 사진으로 돌아왔을 때 «저장 전 번호» 가 보일 수 있다. 그 화면에서 다시 저장하면 방금 고친 것을 옛 번호로 덮어쓴다.
   - 클라이언트: 저장 성공 때 그 사진의 미리 받은 항목을 지운다. `fromOriginal`(원본 다시 불러오기)과 `layer` 가 다르면 다른 키로 둔다.
   - 서버 C07 캐시: 지문에 고친 번호·팀 초벌·원본 번호·이진 마스크의 mtime·크기를 **전부** 넣는다(`source_of` 가 셋 중 하나를 고른다). **저장 경로의 `load_inst`(`instances.py` 482줄 근처)는 캐시를 쓰지 않는다.** `serve_instances` 에서만 쓴다.
   - → 체크리스트에 코드 항목 C19 로 추가했다.
2. **PNG 3~4MB 자체를 줄이는 길.** 감사는 «미리 받기» 만 제안했다. 화면에 보이는 용도라면 `/img` 를 JPEG(q90 안팎)로 주는 보기용 경로가 4MB → 0.5MB 급이다. 다만 라벨링 판단(색·경계)에 영향이 없는지 사람이 봐야 하고 좌표는 같아야 한다. 이번 사이클은 «제안만», 넣을지는 미정(확신 낮음).
3. **실서버 지연은 안 쟀다.** 감사 §7 이 스스로 적었다. 사용자는 VS Code Remote·포트 포워딩으로 접속하니 메모리 기록대로 대역폭이 ~9MB/s 라면 사진 한 장이 0.4초 이상이다. 그래서 C06 은 감사가 매긴 것보다 **더 높은 우선순위**가 맞다.
4. **감사 범위 밖이지만 다인 작업에 관련된 것.** 저장 시 «내가 연 뒤 다른 사람이 저장했는가» 를 보는 코드를 못 찾았다(`instances.py` 에 `lock_for` 로 동시 쓰기만 직렬화). 두 사람이 같은 사진을 열면 마지막 저장이 이긴다. 라벨러가 3~4명이고 과일·구간을 나누면 드물다. 새 코드 항목으로 올리지는 않고 «미확인 위험» 으로만 적는다.
5. **긴 작업 세션의 메모리·프레임.** 사과(열매 99개, 1080×1920)에서 되돌리기 스택이 쌓일 때 메모리, 붓질 중 실제 프레임(HUD 다시 그리기만 잼)은 안 쟀다. C13 을 하기 전에 한 번 재는 게 낫다.
6. **확인창 «저장 안 하고 넘어가기» 가 없다**(`paint.js` 896줄: 확인 = 저장, 취소 = 머묾). 감사 §4 에는 있는데 §5 표에서 빠졌다. 작은 기능이라 C06 과 함께 하면 된다. 별도 항목은 만들지 않았다.

## 3. 과한 것 · 순서 조정
| 항목 | 의견 |
|---|---|
| C06 | **1순위 유지**, C19 조건 포함. 빠르게 D 를 또 눌렀을 때 «마지막 요청 기억» 을 같이 하면 좋다. |
| C07 | 2순위. 단 C06 이 먼저 되면 체감 이득은 절반 이하. 지문에 mtime 을 다 넣기 어려우면 ETag 없이 미루어도 된다. |
| C11 대비 | **유지**. CSS 색 몇 개라 싸고 위험이 없다. |
| C09 | **줄이기**. `#msg` `aria-live`, 도구 `aria-pressed`, 과일·사진·찾기 `aria-label` 정도만. 탭 제목에 사진 이름·`aria-haspopup` 는 실제 사용자(연구실 몇 명, 스크린리더 없음)에 비해 과하다. 한 줄씩이라 비용은 작지만 우선순위 낮음. |
| C08·C10 | **낮게**. 툴이 마우스로 칠하는 것이 전제다(감사 §7). 팔레트 키보드 이동보다 «숫자키로 색 고르기» 같은 라벨러 단축키가 더 값질 수 있으나 이번엔 요구가 없다. 접근성 점수가 목적이면 유지. |
| C12 작은 화면 | **과함 → 보류 권고**. 800×600 은 실사용 화면이 아니다. 1024×640 도구 옵션 스크롤 정도만 보고 싶다면 그것만. |
| C13 | 3순위. 117ms 는 한 번뿐이고 붓질을 끝낸 뒤라 체감 작음. 먼저 재고 결정. `progress` 커서 한 줄은 그냥 해도 된다. |

## 4. 한 줄 결론
감사는 정확하다(속성 0건 확인). 고칠 순서는 **C06(+무효화 조건) → C07 → C11 → C09 최소판 → C13 → 나머지**. C12 는 보류, «JPEG 보기용 경로» 는 사람이 판단할 제안으로 남긴다.
