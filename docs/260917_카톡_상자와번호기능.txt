보안 관련 값·설정 세부는 공개본에서 생략했습니다.

1) 상자(네모) 기능
편집 화면에서 X 키를 누르면 사진 위에 투명 필름이 덮이고 그 위에 네모를 칠 수 있습니다.
드래그로 새 상자, V 누르고 클릭하면 고르기, 고른 상자는 안쪽을 끌어 옮기고 흰 모서리로 크기를 바꿉니다. Del 로 지우고 Ctrl+S 로 저장합니다.
«마스크에서 초벌 생성» 을 누르면 AI 제안 마스크의 덩어리마다 상자를 하나씩 만들어 줍니다. 네 과일 다 됩니다(제안 마스크가 4,823장 전부 있음).
초벌은 저장하지 않습니다. AI 가 틀릴 수 있으니 사람이 고치고 저장을 눌러야 파일이 됩니다.
초벌이 처음엔 번호를 안 쓰고 있어서 고쳤습니다. 지금은 열매 번호가 있으면 번호마다 상자 하나가 나옵니다.
실측으로 사과 10장에서 411개, 블루베리 10장에서 363개가 번호 수와 정확히 같았습니다. 전수로도 사과 1,001장 중 1장만 하나 차이가 났습니다. 원인은 찾았습니다. `20150921_131234_image451` 의 번호 12가 2화소짜리 조각이라 4화소 미만은 빼는 규칙에 걸린 것입니다.
형이 만든 `review_list.csv` 의 x397 과 `suspects_tiny.csv` 에 이미 «불확실» 로 올라와 있는 건입니다. 저희 실측으로는 오류로 확정해도 될 것 같습니다.
번호가 많은 사진은 초벌이 오래 걸렸는데 고쳤습니다. 블루베리 204개짜리가 7.55초였고 지금은 0.2초 안에 나옵니다. 결과는 예전과 좌표까지 같은 것을 확인했습니다.
«YOLO 로 내보내기» 를 누르면 data/<과일>/boxes_yolo/*.txt 가 생깁니다. 형식은 형이 쓰는 것과 같습니다.

🔴 확인 하나 부탁드립니다. 상자 종류 번호입니다.
우리 툴은 과실 0번, 송이 1번, 기타 2번입니다. 형 포도 학습 설정(yolo_grape/cv1/grape.yaml)은 클래스가 하나뿐이고 송이가 0번이었습니다.
좌표 형식은 완전히 같고 번호만 다릅니다. 어느 쪽으로 맞출까요. 아니면 과일마다 번호 표를 따로 둘까요.

2) 열매 번호(인스턴스) 편집 — 지시서 그대로 적용 중
서버 쪽은 끝났습니다. 사과 마스크의 번호를 0/255 로 뭉개지 않고 uint16 그대로 주고받습니다.
저장하면 번호본은 data/<과일>/instances_fixed/ 에, 이진본은 기존 masks_fixed/ 에 같이 씁니다. 세그 팀 흐름은 그대로입니다.
블루베리는 형이 만든 watershed 초벌(bbox_outputs/blueberry/all/instance_maps)을 번호 레이어 초기값으로 읽습니다.
사과 번호 오류 CSV 38행 32장도 툴이 읽습니다. 목록에서 그 사진을 앞으로 올리고 편집 화면에 점선 상자로 표시할 예정입니다.
화면 쪽(지우기 D · 합치기 M · 나누기 X · 새로 붙이기 N)도 다 만들었습니다. 다만 브라우저로 눈으로 본 확인은 아직 아무도 못 했습니다. 체크리스트를 따로 드리겠습니다.
내보내기에 --instances 옵션도 붙였습니다. 사과 3장으로 확인했는데 번호가 그대로 유지됩니다(원본과 화소 단위 일치).

3) 검수
두 기능 다 5회 검수에 태웁니다. 작업 Opus 5 → 검수 Opus 5 → 최종 Fable 순서로 돌리고, 토요일에 Codex 가 마지막으로 봅니다.
지금까지 찾은 버그는 세 개입니다. 확대 상태에서 상자가 두 배로 움직이던 것, 상자 3,000개 넘으면 초과분이 조용히 사라지던 것, 크기 조절에서 모서리를 반대편으로 끌면 상자가 1픽셀로 붕괴하던 것. 셋 다 고쳤습니다.

4) 사람이 눌러 봐야 하는 것
AI 는 서버에 화면이 없어서 마우스·캔버스 동작을 눈으로 본 적이 없습니다. 함수 단위 검사만 수백 개 통과했습니다.
그래서 크롬에서 눌러 볼 체크리스트를 따로 만들어 뒀습니다. kds0206/문서/260917_툴_사람확인_체크리스트.md 입니다.
사과 번호 편집, 블루베리 초벌, 상자, 두 모드 키 충돌, 복숭아·포도가 전과 같은지, 되돌리기, 초벌 개수까지 일곱 묶음입니다.

5) 형한테 확인 부탁드릴 것 (블루베리 초벌)
블루베리 초벌 번호(instance_maps) 1,195장을 전수 대조했습니다. 239장(20%)에서 초벌의 전경이 팀 표준 이진 마스크보다 좁습니다.
마스크는 전경인데 번호가 없는 화소가 합 61,620개이고, 한 장 최대 5,887개, 중간값 2개입니다. 반대 방향은 0입니다.
알 크기로 추정하면 번호를 못 받은 알이 21장에 25개입니다. 전체 45,124개의 0.06%입니다. 목록은 cycle_4/stage2/bb_quant.json 의 est_missed 가 0보다 큰 행입니다.
툴 쪽은 이 자리를 임의로 채우지 않고, 내보낼 때 장마다 화소 수를 적어 넘기도록 고칩니다.

여쭐 것 두 가지입니다.
하나, 초벌을 다시 만들어 «번호 전경 = 마스크» 를 맞추실지입니다. 지금은 사람이 고친 번호가 0장이라 다시 만들어도 잃는 작업이 없습니다. 이후에는 손실이 생깁니다.
둘, 카운팅 벤치마크 100장에 이 21장을 넣을지입니다.

🔴 그리고 앞서 보낸 것에서 정정할 것이 있습니다. 어긋남이 전부 초벌 데이터 탓이라고 적었는데, 검수에서 일부는 저희 코드 문제로 드러났습니다.
번호본과 이진본을 고르는 우선순위가 어긋나 사과 한 장에서 없는 번호가 1,034화소 생겼습니다. 이쪽이 더 나쁜 방향입니다.
저희는 규칙을 하나로 정해 고칩니다. 이진 마스크가 번호 마스크를 자르는 쪽으로 맞춥니다.

6) 포도 송이 번호
CERTH 원본 송이 번호를 툴이 읽을 형태로 2,502장 전부 변환해 뒀습니다. 송이 9,832개가 그대로 살아 있고 전경도 우리 마스크와 정확히 맞습니다.
툴에 켜는 것은 교수님께 전경 기준을 여쭌 뒤에 하겠습니다. 켜면 포도도 블루베리처럼 번호 단위로 셀 수 있습니다.

7) 아까 드린 임시 규칙 두 줄은 해제됐습니다
저녁에 원인을 고쳤습니다. «번호 저장» 이 전경인데 번호 없는 자리를 지우던 문제입니다. 쓰기 규칙을 바꿔서 이제 지워지지 않습니다.
다른 사람이 만든 시험을 쓰지 않고 새로 짠 두 경로로, 새 사진 여덟 장에서 단정 303개를 돌려 실패 0으로 확인했습니다. 블루베리와 사과 모두 평소대로 쓰시면 됩니다.
한 가지만 알고 계시면 됩니다. 구멍이나 브러시로 넓힌 자리에 N 으로 새 번호를 붙였다가 그 번호를 다시 지우면 그 자리도 마스크에서 함께 빠집니다. 규칙상 당연한 동작이고 되살리려면 브러시로 칠하거나 «번호 되돌리기» 를 누르면 됩니다.
포도 번호는 여전히 켜지 않았습니다. 교수님께 전경 기준을 여쭌 뒤에 켭니다.

8) 내보내기 산출물은 지금 넘겨도 됩니다
export --instances 로 나온 번호본을 쓰시면 됩니다. manifest 에 instances_check 칸을 넣었습니다. 장마다 «전경인데 번호 없는 화소» 수가 적혀 있습니다. 예를 들어 (144)_121 은 151입니다.
없는 번호가 생기는 방향은 0입니다. 그쪽은 오늘 고쳤습니다.
