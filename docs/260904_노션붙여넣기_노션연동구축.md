# 2026-09-04 곽동신 — 노션 연동 정리 (서버 토큰 방식 폐기, 역할 분담 확정)

## 왜 봤나
서버에서 한 작업을 노션 AgriVision에 매번 손으로 옮겨 적고 있었다.
자동으로 올라가게 만들 수 있는지 확인해 봤다.

## 결론
서버에서 노션 API를 직접 쓰는 방식은 **불가능하다. 폐기했다.**
대신 로컬과 서버의 역할을 나눴다.

- 노션 읽기와 백업은 로컬 클로드가 한다
- 노션에 쓰는 것은 서버가 만든 md를 사람이 붙여넣는다
- md 사본 보관과 검색은 서버가 한다

## 왜 안 되나
곽동신 계정은 교수님 워크스페이스의 게스트다.
로컬 크롬으로 노션 개발자 도구 페이지를 직접 확인했다.

- 신규 연결: "이 워크스페이스에서 연결을 생성할 권한이 없습니다". 생성 버튼 비활성
- 개인 액세스 토큰: "이 워크스페이스에서 토큰을 생성할 권한이 없습니다". 같은 상태
- 워크스페이스 선택 드롭다운 자체가 없다. 게스트라 단일 워크스페이스다

우회 방법도 없었다.
- AgriVision 페이지는 웹 공개가 꺼져 있어 로그인 없이는 본문이 안 보인다
- 개인 워크스페이스에서 만든 키는 다른 워크스페이스 페이지에 통하지 않는다
- 읽기만 하는 것도 같은 키가 필요하다

## 교수님께 권한 변경은 요청하지 않는다
얻는 게 없다. 로컬 클로드로 이미 되고 있다.
서버는 팀 공용 계정이라 워크스페이스 토큰을 거기에 두는 것도 적절하지 않다.

## 로컬은 왜 되나
로컬 클로드의 노션 커넥터는 워크스페이스 토큰이 아니라 사용자 계정 OAuth다.
본인 계정으로 접근하는 방식이라 게스트여도 정상 동작한다.
9월 2일에 이미 블루베리 페이지 6개를 읽어 외장하드 노션백업 폴더에 md로 저장해 뒀다.

## 만든 것
- `tools/notion_import.py`
  로컬에서 올린 노션 백업 zip을 서버 미러에 푸는 도구.
  `platform/01_references/notion/<YYMMDD>_로컬백업/` 에 풀고 목차 `_INDEX.md`를 만든다.
  윈도우 zip의 깨진 한글 파일명을 복구한다.
  기존 백업은 지우지 않는다. 같은 날짜면 뒤에 번호를 붙인다.
- `.claude/skills/notion-log/SKILL.md`
  서버 클로드가 따르는 규칙. 노션 API를 시도하지 말고 미러를 읽거나 붙여넣기용 md를 만들라는 내용.
- `문서/260904_노션연동_사용법.md`
  역할 분담과 절차 전체.

## 폐기한 것
`tools/_보류_260904_notion_api/` 로 옮겼다. 실행하지 않는다.
- `notion_log.py` 서버에서 노션 API로 읽고 쓰려던 도구
- 슬래시 명령 두 개
- `문서/_폐기_260904/` 교수님께 보내려던 부탁 문구

나중에 계정이 멤버로 올라가면 그때 다시 꺼내면 된다.

## 앞으로 이렇게 쓴다
- 노션에 올릴 내용이 필요하면 서버 클로드에게 "노션에 올릴 거 정리해줘"
  그러면 붙여넣기용 md를 만들어 준다. 열어서 전체 복사 후 노션에 붙여넣으면 된다
- 노션 내용을 서버로 가져오려면 로컬 클로드로 md를 뽑고 zip으로 묶어
  `platform/01_references/notion/` 에 올린 뒤 `python3 tools/notion_import.py <zip>` 실행
- 폴더 드래그는 금지다. 반드시 zip 한 개로 올린다
