## 3. 남은 결함 하나 — N6 «번호 저장이 번호 없는 전경을 지운다»

- **무슨 일**: 번호 레이어가 있는 사진에서 «번호 저장» 을 누르면 — 고쳤든 안 고쳤든 — **이진 마스크의 전경 중 번호가 없던 자리**가 `masks_fixed` 에서 사라집니다. 블루베리 초벌은 239장(20%)에서 그런 자리가 있고(합 61,620화소), 브러시로 방금 넓힌 자리도 같이 지워집니다. 블루베리 `Camera 1 Video (144)_121` 에서 아무것도 안 고치고 저장만 눌러 **151화소가 사라지는 것**을 실측했습니다. 원본 파일은 안 건드리므로 «번호 되돌리기» 로 되돌릴 수는 있지만 그 사진의 번호 편집도 같이 사라집니다.
- **오늘까지 실제 손실**: **0** (사과·블루베리에 저장된 번호 파일이 아직 0장).
- **판정**: 읽기 규칙(«이진본이 번호본을 자른다»)은 맞고, **쓰기 규칙을 고칩니다** — «번호 저장은 **번호가 있던 화소만** 이진본에서 뺄 수 있다». 코드 약 6줄(`app/instances.py` 의 `api_save_instances`, 원본 판정서 ③-2 에 그대로 적음).
- **언제**: 5회 검수와 **별건 «N6 보충»** 으로 — 고침(1차) → 독립 재현(2차). 토요일 Codex 전(금요일) 권고. 이것이 끝나야 블루베리 «번호 저장» 과 포도 켜기를 시작합니다.
- **그 전까지 사람 규칙**: ① 블루베리에서 «번호 저장» 누르지 않기 ② 사과에서 브러시로 넓힌 뒤 번호 저장하지 않기 ③ 포도 켜지 않기.

## 10. 토요일 Codex 에게 물을 것

1. N6 고침 규칙 `masks_fixed = (번호>0) | (이진본 전경 & 잘린 번호본==0)` 의 반례 — 나누기 선, 구멍 위 `N`, 두 번째 저장, 화면의 최대 번호 관리.
2. `app.js` 손으로 쓴 16비트 PNG 해독기(`DecompressionStream("deflate")` · 필터 0~4 · Paeth · 16비트 big-endian)가 맞는가 — 우리는 브라우저에서 본 적이 없다.
3. 번호 저장(`inst:` 자물쇠)과 브러시 저장(`mask:` 자물쇠)이 동시에 오면 `masks_fixed` 가 덮어써지는가, 최소 수정은.
4. 읽을 때 자르는 규칙이 `layer=gt`(원본 번호 그대로) API 에도 걸리는 것이 맞는가.
5. YOLO `%.6f` 반올림으로 1.0 을 5e-7 넘는 것을 두는 판정과 클래스 대응표(다)안이 ultralytics 파이프라인에 안전한가.
