# 포도 실험, 무엇을 했고 무엇이 나왔나 — 아주 쉽게

> 곽동신 님이 읽는 문서입니다. 딥러닝 배경지식 없이 읽을 수 있게 썼습니다.
> 실험 날짜: 2026-07-31 12:01 ~ 16:29 (4시간 28분, GPU 6장)

## 1. 한 문장으로

**포도 사진 100장으로, 딥러닝 모델 54가지를 전부 돌려서 "어떤 조합이 포도를 제일 잘 찾아내는지" 순위를 매겼습니다.**

## 2. 그래서 뭘 하는 실험인가 — 그림으로 이해하기

### 우리가 풀려는 문제: 세그멘테이션

사진에서 **포도가 있는 픽셀(점)을 전부 색칠**하는 일입니다. 컴퓨터한테
"이 점은 포도, 이 점은 배경" 을 픽셀 하나하나 판단하게 시킵니다.

```
   원본 사진                    정답 마스크
 ┌─────────────┐            ┌─────────────┐
 │   🍇  잎    │            │   ███       │   ← 흰색 = 포도
 │  🍇🍇  줄기 │    →       │  █████      │   ← 검은색 = 배경
 │     잎      │            │             │
 └─────────────┘            └─────────────┘
```

컴퓨터가 칠한 것과 정답이 **얼마나 겹치는지**를 점수로 매기는데, 그게 **IoU** 입니다.

### IoU 가 뭔가 (제일 중요한 숫자)

**"겹친 부분 ÷ 합친 부분"** 입니다. 1에 가까울수록 좋습니다.

```
정답:    ■■■■□        겹친 곳: 3칸
예측:    □■■■■        합친 곳: 5칸
                      IoU = 3/5 = 0.6
```

우리 최고 점수가 **0.8586** 이니, **약 86% 를 맞춘 것**입니다.

### 모델은 "백본 + 헤더" 두 부품으로 되어 있습니다

```
사진 → [ 백본 ]  →  [ 헤더 ]  →  색칠한 결과
        눈 역할      판단 역할
```

- **백본(backbone)** = **눈**. 사진에서 "여기 동그란 게 있네, 여기 초록색이네" 같은
  **특징을 뽑아내는** 부분입니다. (ResNet-50, ConvNeXt-T, Swin-T ...)
- **헤더(head)** = **판단**. 백본이 뽑은 특징을 받아서 **픽셀별로 최종 결정**을
  내리는 부분입니다. (U-Net, FPN, FaPN ...)

**이 연구의 질문**: *"눈을 바꾸는 게 중요한가, 판단을 바꾸는 게 중요한가?"*

기존 논문들은 "SegFormer가 좋다" 처럼 **완성품 이름**으로만 비교해서,
좋아진 이유가 눈 때문인지 판단 때문인지 알 수가 없습니다. 그래서 우리가
**부품 단위로 전부 교차해서** 비교하는 겁니다.

## 3. 실험 설계 — 왜 이렇게 했나

| 항목 | 값 | 왜 이렇게 했나 |
|---|---|---|
| 사진 | **100장** | 교수님 지시. "빨리 돌려서 결과 그림부터 보자" |
| 나누기 | **70 / 10 / 20** | 학습용 70장 · 중간점검 10장 · **최종시험 20장** |
| 헤더 | **9종** | 팀 논문 초안이 정한 목록 그대로 |
| 백본 | **6종** | 7종 계획이었으나 1종은 우리 GPU에서 안 돌아감(아래 5절) |
| 조합 | **9 × 6 = 54가지** | 교수님: *"조합은 다 해보세요"* |
| 반복 | 200번(에폭) | 팀 합의 |

**중요**: 최종 시험용 20장은 **학습에 한 번도 안 쓴 사진**입니다.
사람으로 치면 "공부 안 한 문제로 시험 보기" 입니다. 이래야 진짜 실력이 나옵니다.

## 4. 결과 — 3가지만 기억하시면 됩니다

### 결과 ① 1등은 **U-Net + ConvNeXt-T** (IoU 0.8586)

| 순위 | 조합 | IoU |
|---|---|---|
| 🥇 | **U-Net + ConvNeXt-T** | **0.8586** |
| 🥈 | U-Net + UniFormer-S | 0.8581 |
| 🥉 | U-Net + Swin-T | 0.8539 |
| ... | | |
| 꼴찌 | FCN + ResNet-50 | 0.6874 |

1등과 꼴찌 차이가 **0.86 vs 0.69** 로 꽤 큽니다. 조합을 잘 고르는 게 의미가 있다는 뜻입니다.

### 결과 ② 🔴 **포도에서는 "판단(헤더)"이 "눈(백본)"보다 중요합니다**

이게 **이번 실험의 진짜 발견**입니다.

| | 1등과 꼴찌의 차이(폭) |
|---|---|
| **헤더**(판단) 9종 | **0.079** ← 더 큼 |
| **백본**(눈) 6종 | 0.057 |

**그런데 블루베리에서는 정반대였습니다.**

| 데이터셋 | 헤더 폭 | 백본 폭 | 뭐가 더 중요? |
|---|---|---|---|
| 블루베리 | 0.008 | 0.065 | **백본**(눈)이 8배 |
| **포도** | **0.079** | 0.057 | **헤더**(판단) |

→ **"과일이 바뀌면 정답이 뒤집힌다."**
이건 우리 논문이 하려는 주장 그 자체입니다. *"작물마다 따로 골라야 한다"* 는
근거가 되니까요. 교수님께 이걸 말씀드리면 좋습니다.

**왜 그럴까** (추측입니다, 확정 아님): 블루베리는 알갱이가 아주 작아서 **잘 보는 눈**이
중요하고, 포도는 송이가 커서 **경계를 잘 다듬는 판단**이 중요한 것으로 보입니다.

### 결과 ③ 눈에 띄는 두 꼴찌

- **FCN(헤더)이 압도적 꼴찌** — FCN은 가장 단순한 판단 방식입니다. "단순한 걸로는
  안 된다" 는 걸 보여주는 **기준선** 역할을 제대로 했습니다.
- **ResNet-50(백본)만 유독 낮음** — 나머지 5개 눈은 서로 거의 차이가 없습니다
  (0.821~0.835 로 촘촘). 즉 **"CNN이냐 트랜스포머냐"의 문제가 아니라
  "옛날 것(ResNet)이냐 요즘 것이냐"의 문제** 로 보입니다.

## 5. 통계 검정 — "우연이 아니다" 를 증명한 부분

점수 차이가 났다고 끝이 아닙니다. **"운 좋아서 그런 거 아니냐"** 는 질문에
답해야 논문이 됩니다. 그게 통계 검정입니다.

우리가 쓴 건 **Friedman 검정** 입니다. 쉽게 말하면
*"같은 시험지 20장을 여러 모델이 다 풀었을 때, 순위가 일관되게 나오는가?"* 를 봅니다.

| 검정 | p값 | 해석 |
|---|---|---|
| 헤더끼리 차이 | 0.000000...(2.6e-88) | **우연일 확률 사실상 0** ✅ |
| 백본끼리 차이 | 0.000000...(5.6e-40) | **우연일 확률 사실상 0** ✅ |

> **p값 읽는 법**: "이 차이가 우연히 생겼을 확률". 보통 **0.05보다 작으면**
> "우연 아님" 으로 인정합니다. 우리 건 0.05보다 **어마어마하게** 작습니다.

### 🔴 여기서 제가 문제를 하나 잡아서 고쳤습니다

원래 팀 논문 초안대로 **54조합을 한꺼번에** 비교하면, 통계적으로 **"차이를 인정받으려면
순위가 20계단 이상 벌어져야 한다"** 는 결과가 나옵니다. 조합은 54개인데 시험지는
20장뿐이라 그렇습니다. 그러면 대부분 "차이 없음" 으로 나와서 **아무 말도 못 합니다.**

그래서 **질문을 둘로 쪼갰습니다.**
- ① 헤더끼리만 비교 (백본은 조건으로 묶음) → 시험지 120장 효과, 비교대상 9개
- ② 백본끼리만 비교 (헤더는 조건으로 묶음) → 시험지 180장 효과, 비교대상 6개

이러니 필요한 순위차가 **20계단 → 1.1계단, 0.56계단** 으로 떨어져서
**유의한 차이를 31쌍이나 찾아냈습니다.** 이게 없었으면 결과가 전부 "모르겠음" 이었습니다.

## 6. 속도·메모리도 쟀습니다

논문 초안이 *"파라미터 수만 갖고 '가볍다'고 주장하면 안 된다"* 고 못박아 놨는데
아무도 안 쟀길래 제가 쟀습니다.

| 항목 | 최소 ~ 최대 | 배수 |
|---|---|---|
| 파라미터(모델 크기) | 21.6 ~ 31.6 M | 1.5배 |
| **FLOPs**(계산량) | 20.5 ~ 47.1 G | **2.3배** |
| **지연시간**(사진 1장 처리) | 9.8 ~ 29.0 ms | **3.0배** |

**읽는 법**: 모델 크기는 1.5배밖에 차이 안 나는데 **실제 처리 속도는 3배** 차이 납니다.
→ **"모델이 작으니 스마트폰에서 돌아간다" 는 말은 근거가 안 됩니다.** 초안 주장이 옳았습니다.

**좋은 소식**: 1등인 **U-Net + ConvNeXt-T 가 속도도 빠른 편**입니다(11.8ms).
보통은 "정확하면 느리다" 인데 이번엔 **둘 다 잡았습니다.**

## 7. 🔴 정직하게 — 이 결과의 한계 4가지

교수님이나 팀원이 물어보면 **이걸 먼저 말씀하셔야** 합니다.

1. **100장은 전체 2,502장의 4% 입니다.** 본 실험이 아니라 **연습**입니다.
2. **나누기를 딱 한 번만 했습니다.** 다르게 나눴으면 순위가 바뀔 수 있습니다.
   (본 실험에서는 5번 다르게 나눠서 반복할 예정입니다)
3. **채점이 사진 가운데 44%만 봅니다.** 코드가 `CenterCrop` 이라 사진 가장자리는
   채점에서 빠집니다. 이건 코드를 고쳐야 하는 문제입니다.
4. **MambaVision 백본은 아예 못 돌렸습니다.** 우리 GPU(V100)가 그 모델에 필요한
   최신 기능이 없습니다. 설치는 성공했는데 **실행이 안 됩니다.** 두 번 시도해서 확인했습니다.
   → 팀이 "빼고 갈지" 결정해야 합니다.
