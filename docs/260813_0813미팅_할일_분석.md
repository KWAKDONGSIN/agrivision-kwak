## 4️⃣ 🔴🔴 코드 구조 md + 센터크롭 프롬프트 — **실질 최우선**

### 왜 최우선인가

이건 **0810 랩미팅 지시 ②번과 같은 것**입니다. 교수님이 그때 **두 번** 지목하셨고,
**결론이 바뀌면 전 실험을 다시 산출해야 합니다.** 3주째 밀려 있습니다.

### 문제의 실체 (숫자로)

- `semseg/augmentations.py:411` — **평가는 사진 정가운데 512×512만** 씁니다 (`CenterCrop`)
- 학습은 `RandomCrop 512` (yaml `TRAIN.IMAGE_SIZE: [512,512]`)
- 🔴 **정규화(2MP)된 사진의 약 44%만 채점**됩니다. 리사이즈를 안 했다면 4K 기준 **약 3%**
- 즉 **모델 성적이 "사진 가운데에 열매가 있었는가"에 좌우**됩니다

### 🔴 어제 확보한 근거를 여기 쓰십시오

**Huang et al. 2018** (arXiv:1805.12219, 위성영상 타일링·스티칭) 원문:

> *"very large images … **too large to be segmented directly using most CNNs**"*
> *"smaller sub-images, called '**patches**', are processed individually and then '**stitched**'
> back together to create a tile-sized label map"*
> *"can result in **discontinuities at output boundaries**"*

→ **큰 사진은 패치로 전부 덮어 추론하고 다시 이어붙이는 것이 표준**이고,
**가운데 한 조각만 채점하는 우리 방식은 비표준**입니다. 이제 근거를 대고 말할 수 있습니다.

### 교수님께 드릴 선택지는 3개로 좁혀집니다

| 안 | 방법 | 장점 | 단점 |
|---|---|---|---|
| **A** | 그대로 센터크롭 유지 | 재산출 없음. 기존 결과 그대로 | **비표준.** 사진의 44%만 채점 — 심사자 지적 확실 |
| **B** | **슬라이딩 윈도우** 평가 (겹쳐서 전체 덮고 스티칭) | Huang 2018 기준 **표준**. 사진 전체 채점 | 평가 코드 신규 작성 + **전 실험 재평가**(학습은 재사용 가능) |
| **C** | **타일링 데이터셋**(`datasets_tiled_512/`)으로 학습·평가 | 겉보기 크기까지 통일(SNIP 근거). 이미 **53,040타일 구축 완료** | **전 실험 재학습.** 기존 결과와 직접 비교 불가 |

🔴 **서버 의견: B 가 현실적입니다.** 학습 결과(체크포인트)를 버리지 않고 **평가만 다시** 하면 되기 때문입니다.
C는 데이터가 이미 있지만 재학습 비용이 큽니다(표본 11배).

### 실제로 할 일

- [ ] **코드 구조 md** — 학습 1회가 어떤 경로로 흐르는지:
      `configs/*.yaml` → `tools/train.py` → `semseg/datasets` → `semseg/augmentations.py`
      → `semseg/models/{heads,backbones}` → `semseg/losses.py` → `val.py` → `output/`
      각 파일이 무엇을 하는지 한 줄씩 + **실제 행번호**
- [ ] **교수님께 드릴 프롬프트/질문서** — 위 A·B·C 3안 + 각 비용(사람·GPU시간) + 서버 추천안 + Huang 2018 근거
- [ ] 결정되면 그때 코드 작성 (**결정 전에 코드부터 짜지 말 것** — 3안이 서로 다른 코드입니다)
