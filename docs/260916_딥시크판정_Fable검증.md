딥시크는 «현재 상태로 제출하면 리젝트» 라는 강한 어조였습니다. 항목별로 파일·숫자와 대조한 결과, **맞는 지적 4개, 사실을 잘못 읽은 것 2개, 과장 2개** 입니다.

## 일치하는 것 (딥시크 = 내 사전 의견)
- **D. amodal(가려진 부분까지 원) 과 visible(보이는 부분만) 이 한 마스크에 섞이면 안 된다.** 둘 다 «visible 로 통일» 이 최소 해법. 딥시크는 «교수 결정으로 미루지 말라» 고 했는데, 통일 방향은 교수님이 정할 일이지만 **정하기 전엔 학습에 쓰지 않는 게 맞다**는 데 동의.
- **E. 포도 «보이는 송이 라벨 누락» 이 표본 84% 면 이대로 벤치마크에 못 쓴다.** 대안도 같음: 툴에서 사람이 전량 재라벨하거나, 포도를 보조 데이터셋으로 격하하거나 제외. 딥시크의 «72장만 검수 대기는 부족, 전수 재라벨 필요» 는 맞는 말 — 72장은 2차가 판정한 표본이고 2,403장(검수판 사용 장수) 전체가 대상입니다.
- **F1. AI 후보 탐지의 정밀도·재현율을 안 쟀다** → 실측으로 답: 후보 139개 중 채택 83개(**정밀도 60%** — 3차가 85개 채택 → 사이클1 재판정으로 2개 제거). 재현율은 모름 — 2차가 «누락» 이라 본 8장에는 AI 후보가 아예 없었으므로 **놓친 것(FN)이 있음은 확실**.
- **F3. 분할표를 바꿨으면 변경 이력을 문서화하라** → 진행 중(작업자 D 가 v4 분할표 + manifest 변경 기록 생성).

## 갈리는 것
- **A. «단일 모델(BackboneUNet×MiT-B2) 초벌로 정답을 보강하면 그 조합에 유리, 결과 무효 수준»**
  - 사실 확인: 채택 기준은 «사진에 복숭아가 분명히 보이는가» 였지 모델 출력 신뢰가 아님. 그리고 **다른 계열 모델(VWFormer 헤더 × ResNet-50 백본)로 교차 확인**한 결과, 채택 83개 중 **54개(65.1%)는 다른 모델도 같은 자리를 절반 이상 잡았고, 69개(83.1%)는 20% 이상 겹침**(사이클1 전 85개 기준으로는 54개 63.5% · 70개 82.4%)(`260916_라벨링툴/final/crosscheck/peach_accepted_vs_vwformer_r50.csv`).
  - 내 판단: **편향 가능성은 인정하되 «무효 수준» 은 과장.** 남은 위험 = 어떤 모델도 못 잡는 누락(FN)은 여전히 빠져 있고, 잡힌 것 중 29개는 MiT-B2 만 잡은 것. 논문에 후보 생성 모델·채택 규칙·교차 확인 수치를 명시하고, 딥시크 3안(보강 전후 정답으로 순위 민감도 분석)을 하면 방어 가능. 이건 인훈 님 0908 옵션 B 와 같은 것.
- **B. «봉인된 시험 풀 12장의 이미지를 교체하고 라벨까지 수정 = 오염, 폐기하라»**
  - 🔴 **사실 오류: 라벨(마스크)은 한 화소도 안 고쳤습니다.** 12장은 «변환 스크립트가 zip 안의 다른 사진 파일을 가져온» 버그라 **이미지 파일을 올바른 것으로 되돌린 것**이고, 마스크는 원본 CERTH 주석과 Dice 1.000 으로 동일함을 확인했습니다(`final/fix_grape_mismatch.py`, `grape_image_fix/fix_records.json`).
  - «Dice 를 봤으니 정보 유출» — 본 것은 «AI 초벌 vs 마스크» 일치도이지 벤치마크 모델의 시험 점수가 아니며, 모델 선택에 쓰지 않았습니다. 다만 **투명한 기록·부록 공개** 요구는 맞고, 그대로 합니다(논문 초안 작업자 D). 딥시크가 말한 «12장 폐기» 는 보수적 대안으로 남겨 둠(교수님 선택).
- **C. «그룹당 1장 제거는 급진적, 같은 fold 배정이 낫다, 임계값이 관대하다»**
  - 임계값 «관대» 주장은 근거 없음: 1차 60쌍 + 완화로 늘어난 34그룹을 2차·3차가 눈으로 봐서 **오탐 0**. 전부 같은 촬영본의 약간 다른 확대.
  - «같은 fold 배정이면 손실 0» — 학습 fold 안에 같은 사진이 두 장 있으면 그 장면의 가중치가 2배가 되고, 시험 fold 에 있으면 같은 사진을 두 번 채점하는 셈. 사용자(곽동신) 지시도 «중복은 빼라». **제거 유지.** 단, 뺀 98장(중복) 목록이 manifest 에 있고 `export_dataset.py --keep-duplicates` 로 되살릴 수 있어 되돌리기 쉬움.
- **F2. «COCO 정답과 IoU 0.986 인데 왜 누락이 있나, 원본 라벨 신뢰 의심»** — 🔴 **질문을 잘못 읽음.** 0.986 은 «우리 마스크 vs 원본 COCO 폴리곤» 이라 «변환이 정확하다» 는 뜻이지 «AI vs 정답» 이 아님. 누락은 원본 주석 자체에 있고, 그래서 사진을 눈으로 본 것.

## 후속 실측 (같은 날 오후) — 딥시크 A 에 대한 정량 답
민감도 분석(`260916_라벨링툴/final/sensitivity/`, 작업 Opus5 → 재검증 Opus5(부트스트랩 1,000회) → 3차 재추론 확인):
- 파일럿 시험 fold(복숭아 25장·포도 500장)에서 4쌍 순위는 **원본 정답과 검수판 정답에서 동일**. 부트스트랩으로 1위가 바뀌는 비율 복숭아 0.3%/0.0%, 포도 3.9%/7.0%(포도 1–2위는 0.0015 차 동점).
- 후보 생성 모델의 **초과 이득 = Dice +0.0077(95% CI [+0.0027, +0.0143]) / 바뀐 9장 한정 +0.0217** → 편향은 실재하나 1–2위 격차(0.020)의 약 40%.
- **추가된 화소 40,734개는 전부 후보 모델 예측 안에 있음.** 2개 이상 모델 합의 화소만 채택하면 초과 이득 +0.0133, 3개 이상이면 +0.0014. 편향의 94%가 단일 모델 단독 화소 → 딥시크 A 는 «규모는 작지만 구조적으로 맞는 지적». 권고: 사람 확인 때 윤곽 재작성, 또는 자동 보강 규칙을 «2모델 합의» 로.

## 사이클1 재검수 반영 (2026-09-16 밤)
- 추가 성분 85개 전수 재판정(Opus5 2단계): 깨끗한 과실 54 / 잎 우세 28 / 오검출 1 / 불명 2. 3차가 오검출 1·경계 번짐 1 제거 → **83개·39장**. 잎 우세 21장은 사람 윤곽 조정 flag. 딥시크 A 의 «후보 모델 윤곽 편향» 은 이 수치로 더 구체화됨(추가 **성분**의 약 35% = 29/83 이 깨끗한 과실이 아님. 화소 기준은 파일럿 40,734px 중 깨끗한 과실 13,216px = 32.4%).
- 논문 초안의 «추가분 = 보이는 부분» 문장은 성립하지 않음 → «모델 예측 범위이며 잎이 덮인 부분을 포함하는 경우가 1/3» 로 고침.

## 딥시크만 짚은 것
- 보강 전후 두 정답으로 상위 조합 순위가 바뀌는지 **민감도 분석**(A-3). 채택 → 다음 할 일에 추가.
- 포도를 «약지도/비지도 벤치마크로 용도 변경» — 교수님 판단 사항으로 기록만.

## 최종 추천 (Fable)
딥시크의 «리젝트» 총평은 B·F2 의 사실 오독 위에 서 있어 그대로 받아들이면 안 됩니다. 그러나 **A(후보 생성 모델 편향)·D(amodal 혼재)·E(포도 라벨 완전성)·F1(탐지 재현율 미측정)은 진짜 약점**입니다. 실행 순서: ① 교수님 결정(amodal·라벨 범위·송이 단위) ② 그 규칙으로 툴에서 사람 재라벨(복숭아 125 전수, 포도 전수) ③ 보강 전후 정답으로 순위 민감도 1회 ④ 논문에 후보 생성 모델·교차 확인 수치·12장 교정 내역 부록. 토요일 Codex 판정 때 이 문서와 딥시크 원문을 같이 주어 3자 대조.
