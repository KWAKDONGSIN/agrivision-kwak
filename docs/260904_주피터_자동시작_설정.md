# 주피터 랩 자동 시작 설정 (포트 5101)

작성: 2026-09-04

## 결론

재부팅돼도 자동으로 살아납니다. **systemd 사용자 서비스**로 등록했습니다.
지금 돌고 있는 주피터는 건드리지 않았습니다.

## 왜 이 방법인가

서버에서 확인한 것입니다.

- `loginctl enable-linger` 가 **root 없이 됐습니다.** 이게 핵심입니다.
  linger 를 켜면 내가 로그아웃해도, 서버가 재부팅돼도 내 systemd 서비스가 살아납니다.
  이게 안 됐으면 cron 의 `@reboot` 를 써야 했습니다.
- systemd 쪽이 cron 보다 낫습니다. **주피터가 죽으면 10초 뒤 자동으로 다시 띄웁니다.**
  cron 은 부팅 때 한 번 실행하고 끝이라 그 뒤에 죽으면 그대로 죽어 있습니다.

## 만든 것

`~/.config/systemd/user/jupyter-lab.service`

들어 있는 내용을 풀어 쓰면 이렇습니다.

- 네트워크가 올라온 뒤에 시작한다
- `/data/project/2026summer/kds0206` 폴더가 보일 때까지 **최대 2분 기다린다**
  (재부팅 직후 `/data` 마운트가 늦게 붙을 수 있어서)
- `/opt/anaconda3/bin/jupyter-lab --no-browser` 를 `/data/project/2026summer` 에서 실행
- 비정상 종료하면 10초 뒤 재시작
- 로그는 `logs/jupyter_kds0206.out` 에 이어 붙인다

보안 관련 값·설정 세부는 공개본에서 생략했습니다.
포트를 또 바꾸고 싶으면 그 파일만 고치면 됩니다.

## 현재 상태

- 부팅 시 자동시작: **enabled**
- 서비스 지금 실행중: **inactive** (일부러 안 켰습니다)
- linger: **yes**

지금 5101 에서 돌고 있는 주피터는 곽동신 님이 `nohup` 으로 직접 띄운 것입니다(PID 2315777).
서비스를 지금 켜면 포트가 겹쳐서 실패하고, 억지로 넘기려면 지금 것을 죽여야 합니다.
**작업 중인 노트북이 날아갈 수 있어서 건드리지 않았습니다.**

## 앞으로 어떻게 되나

**아무것도 안 해도 됩니다.** 다음 재부팅 때 서비스가 알아서 5101 에 띄웁니다.

지금 당장 서비스 관리 방식으로 바꾸고 싶으면, **작업 중인 노트북을 모두 저장한 뒤**
아래를 실행하세요. 급하지 않습니다.

```bash
kill 2315777
systemctl --user start jupyter-lab
systemctl --user status jupyter-lab
```

## 자주 쓸 명령

```bash
systemctl --user status jupyter-lab     # 상태 보기
systemctl --user restart jupyter-lab    # 다시 시작
systemctl --user stop jupyter-lab       # 멈춤
systemctl --user disable jupyter-lab    # 자동시작 끄기
journalctl --user -u jupyter-lab -n 50  # 서비스 로그
tail -f /data/project/2026summer/kds0206/logs/jupyter_kds0206.out   # 주피터 로그
```
